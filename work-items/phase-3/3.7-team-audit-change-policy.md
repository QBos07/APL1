# 3.7 — Define and record before/after values for team changes

**Status:** Not started  
**Goal:** Decide which team fields are auditable and make common profile changes understandable in history.

## Initial field policy

- Create: record new team name and notes as new values; old values are absent.
- Rename/edit: record only fields that actually changed, with old and new values.
- Archive/unarchive if unarchive is later supported: record the archive state transition.
- Do not copy the entire team row into the audit log; avoid irrelevant timestamps/derived fields.
- Financial fields are not in the team profile and will receive a separate policy in the money phase.

## Work list

- [ ] Review and confirm the initial field policy above.
- [ ] Define normalized representation for null/empty text, booleans, and timestamps in `audit_changes`.
- [ ] Update team use cases to pass only changed field values to the audit repository.
- [ ] Avoid emitting a change row when a saved value is unchanged.
- [ ] Add unit/integration tests for create, rename one field, edit notes, no-op update, and archive transitions.
- [ ] Document that audit change values are a local explanation/history feature, not a tamper-proof record.

## Acceptance checks

- [ ] History displays exactly the fields changed and their old/new values.
- [ ] A no-op update does not claim that values changed.
- [ ] Create/archive transitions represent absent/boolean values unambiguously.
- [ ] Field changes commit atomically with the team operation and audit event.
- [ ] Tests confirm no financial or unrelated data is copied into team audit payloads.
