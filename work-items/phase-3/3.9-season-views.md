# 3.9 — Build season/period views

**Status:** Not started  
**Goal:** Let the user organize team records into manually created seasons or reporting periods.

## Work list

- [ ] Add a Seasons/Periods sub-view under the Teams tab (or another documented location that does not add an unplanned primary tab).
- [ ] List active periods for the active team and provide an explicit include-archived filter.
- [ ] Add detail and interactive create/edit/archive dialogs for label, optional dates, and notes.
- [ ] Show a selected/current period only after the user explicitly selects one; do not assume the current calendar year is a season.
- [ ] Preserve list context and use 3.1 validation/use cases.
- [ ] Add command handoff for `:season` actions through [3.12](3.12-reference-commands.md).
- [ ] Test empty, archived-only, and populated states plus keyboard/mouse dialog behavior.

## Acceptance checks

- [ ] User can create a period with a label only or add dates/notes manually.
- [ ] No period or dates are generated on first launch or team creation.
- [ ] Selecting a period changes only view context and does not edit records.
- [ ] Archived periods remain visible to historical browsing but are absent from current pickers by default.
- [ ] Team-scoped lists do not show another team's periods.
- [ ] Menu, dialog, and command paths invoke the same validation and persistence operations.

## Dependencies / boundaries

- Depends on [3.1](3.1-season-records.md), Phase 2 vertical tabs/window layout (2.16, 2.19), and interactive dialogs (2.23).
- This view does not generate events or link results until later phases.
