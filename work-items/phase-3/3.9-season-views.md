# 3.9 — Build season/period views

**Status:** Implemented (2026-11-24)  
**Goal:** Let the user organize team records into manually created seasons or reporting periods.

## Work list

- [x] Add a Seasons/Periods sub-view under the Teams tab (or another documented location that does not add an unplanned primary tab).
- [x] List active periods for the active team and provide an explicit include-archived filter.
- [x] Add detail and interactive create/edit/archive dialogs for label, optional dates, and notes.
- [x] Show a selected/current period only after the user explicitly selects one; do not assume the current calendar year is a season.
- [x] Preserve list context and use 3.1 validation/use cases.
- [x] Add command handoff for `:season` actions through [3.12](3.12-reference-commands.md).
- [x] Test empty, archived-only, and populated states plus keyboard/mouse dialog behavior.

## Acceptance checks

- [x] User can create a period with a label only or add dates/notes manually.
- [x] No period or dates are generated on first launch or team creation.
- [x] Selecting a period changes only view context and does not edit records.
- [x] Archived periods remain visible to historical browsing but are absent from current pickers by default.
- [x] Team-scoped lists do not show another team's periods.
- [x] Menu, dialog, and command paths invoke the same validation and persistence operations.

## Dependencies / boundaries

- Depends on [3.1](3.1-season-records.md), Phase 2 vertical tabs/window layout (2.16, 2.19), and interactive dialogs (2.23).
- This view does not generate events or link results until later phases.

## Implementation notes (2026-11-24)

- Seasons/periods are reachable from team detail (`o`), the window-bar Records menu, and commands. The list hides archived rows by default; `a` includes them.
- Detail and create/edit/archive dialogs use the 3.1 service. Selecting a period (`s` or `season select`) changes only view context; the selected label is shown next to the active team in the status bar and success feedback confirms the selection. No calendar year or period is generated.
