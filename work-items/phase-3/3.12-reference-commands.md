# 3.12 — Add commands for Phase 3 reference records

**Status:** Not started  
**Goal:** Make driver, membership, season, and car actions available through the Phase 2 ex-style command system.

## Work list

- [ ] Add `:driver list`, `:driver new`, and `:driver show <id-or-name>` routes.
- [ ] Add `:membership add` and `:membership end` routes scoped to the active team by default.
- [ ] Add `:season list`, `:season new`, and `:season select <label-or-id>` routes.
- [ ] Add `:car list`, `:car new`, and `:car show <id-or-identifier>` routes.
- [ ] Complete navigation/selection commands directly when unambiguous; open prefilled dialogs for incomplete create/update actions.
- [ ] Execute fully specified commands directly through the same validation/use case as dialogs; ask the user to choose when names are ambiguous.
- [ ] Add command help/completion entries from the shared registry and tests for active-team scoping.
- [ ] Add parity tests comparing menu/dialog and command outcomes for each record type.

## Acceptance checks

- [ ] Commands cannot bypass domain validation, audit behavior, or database transactions.
- [ ] Incomplete commands open the correct dialog with supplied arguments prefilled.
- [ ] Complete valid commands execute once and report success; invalid commands write nothing.
- [ ] Team-scoped membership/season/car commands default to the active team and identify that scope before a potentially ambiguous write.
- [ ] Duplicate names/identifiers resolve to a choice dialog rather than an arbitrary record.
- [ ] Command help documents the implemented syntax and does not claim unavailable options.

## Dependencies / boundaries

- Depends on Phase 2 command UI/parser/dispatch redesign items 2.25–2.27 and the corresponding Phase 3 use cases/screens.
- Money, development, parts, and event commands remain in later phases.
