# 3.11 — Add a team-scoped activity history view

**Status:** Not started  
**Goal:** Let the user inspect team create/rename/archive activity and field changes from the History tab.

## Work list

- [ ] Add a History body view that reads audit events for the active team by default.
- [ ] Display timestamp, action, record type/name, and concise summary; distinguish entered record dates from system audit timestamps.
- [ ] Open an activity detail dialog/view showing field-level old/new values when present.
- [ ] Add basic filters for action/entity type and date range; show active filters and an empty state.
- [ ] Keep archived teams and their history accessible through an explicit team selection/history scope.
- [ ] Ensure audit presentation is read-only; no edit/delete action for history rows.
- [ ] Add tests for event ordering, team filtering, no-change/create/archive details, and empty state.

## Acceptance checks

- [ ] Team create/rename/archive events from 3.6 are visible and link to the correct stable team record.
- [ ] Before/after values from 3.7 are readable and omitted when there was no prior value.
- [ ] Default history is scoped to the active team; an all-team view requires explicit selection.
- [ ] History records cannot be altered from the UI.
- [ ] Filters can be cleared and returning from detail preserves the filtered list position.
- [ ] The view does not fabricate an activity for records that predate audit support.

## Dependencies / boundaries

- Depends on [3.5](3.5-audit-schema-repository.md), [3.6](3.6-team-audit-events.md), [3.7](3.7-team-audit-change-policy.md), and Phase 2 History tab/dialog support.
- General search, export, and history for all later feature types are extended in Phase 8.
