# 3.6 — Record team create, rename, and archive activity

**Status:** Not started  
**Goal:** Make Phase 2 team mutations produce traceable audit events in the same transaction as the team change.

## Work list

- [ ] Update team create use case to append a `team_created` activity event after obtaining the new stable team ID.
- [ ] Update team rename use case to append a `team_renamed` event with a concise record reference.
- [ ] Update team archive use case to append a `team_archived` event, including active-team fallback context where useful.
- [ ] Use the same caller-owned transaction for team mutation, active-team fallback changes, and audit event insertion.
- [ ] Keep audit repository calls out of TUI handlers; menus/dialogs/commands continue through the same team use cases.
- [ ] Add integration tests for event contents and failure injection proving team and audit state roll back together.

## Acceptance checks

- [ ] Each successful create/rename/archive action has exactly one corresponding activity event.
- [ ] A rejected validation or failed database operation creates no audit event.
- [ ] If audit insertion fails, the related team mutation and active-team change are rolled back.
- [ ] Events reference the team by stable ID and remain available after team archive/rename.
- [ ] Repeating an idempotent archive does not create misleading duplicate activity, according to the documented operation contract.
