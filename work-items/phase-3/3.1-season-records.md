# 3.1 — Add user-created season/period records

**Status:** Not started  
**Goal:** Let a team create its own season or reporting-period labels without generated calendars or assumed years.

## Proposed record

- Stable ID and owning team ID.
- User-entered required label/name.
- Optional user-entered start date, end date, and notes.
- Archived state and system-maintained created/updated timestamps.

Proposed rules: labels are trimmed, non-empty, and case-insensitively unique within a team (including archived periods); if both dates are supplied, start must not be after end. Dates are optional and entered explicitly.

## Acceptance checks

- [ ] A team with no user-created season has zero season rows; no calendar/year is generated.
- [ ] A season is always associated with a stable team ID.
- [ ] Blank names and duplicate labels within a team are rejected using the documented case policy.
- [ ] Missing dates remain missing; supplied invalid/reversed dates are rejected.
- [ ] Archived seasons remain readable for history but are omitted from default current-season pickers.
- [ ] Tests prove one team's seasons do not appear in another team's default list.
