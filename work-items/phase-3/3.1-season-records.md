# 3.1 — Add user-created season/period records

**Status:** Implemented (2026-11-24)  
**Goal:** Let a team create its own season or reporting-period labels without generated calendars or assumed years.

## Proposed record

- Stable ID and owning team ID.
- User-entered required label/name.
- Optional user-entered start date, end date, and notes.
- Archived state and system-maintained created/updated timestamps.

Proposed rules: labels are trimmed, non-empty, and case-insensitively unique within a team (including archived periods); if both dates are supplied, start must not be after end. Dates are optional and entered explicitly.

## Implementation notes (2026-11-24)

- SQLite migration 4 creates `seasons` with a team foreign key, case-insensitive `(team_id, label)` uniqueness, optional ISO dates, archive state, and system timestamps. No season is seeded.
- `season_repository` and `season_service` provide team-scoped create/list/get/update/archive operations. Labels/notes are trimmed; dates accept only real `YYYY-MM-DD` values and reversed ranges are rejected.
- Tests: `test_reference.c`, `test_season_repository.c`, and `test_reference_services.c` cover blank/duplicate labels, missing and invalid dates, archive visibility, stable IDs, and cross-team isolation.
