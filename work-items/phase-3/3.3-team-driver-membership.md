# 3.3 — Add dated team-driver membership records

**Status:** Implemented (2026-11-24)  
**Goal:** Preserve which team a driver represented during a user-entered time period, even after a roster change.

## Proposed record

- Stable membership ID, team ID, and driver ID.
- Required user-entered start date; optional end date.
- Optional role/seat label and notes supplied by the user.
- System-maintained timestamps.

Each membership period is a separate record; rejoining creates another period rather than rewriting old affiliation. No contract or seat assignment is inferred.

## Acceptance checks

- [x] A driver can have multiple dated membership periods without prior periods being overwritten.
- [x] Current-team roster queries include only memberships for that team that have no end date, unless a historical date is explicitly requested.
- [x] Historical queries can resolve the exact membership by stable ID and date range.
- [x] Invalid team/driver references and invalid date ranges do not write partial records.
- [x] Team A cannot list or alter Team B's memberships through a team-scoped operation.
- [x] The application does not automatically set dates or create a membership when a driver profile is created.

## Implementation notes (2026-11-24)

- SQLite migration 6 creates `team_driver_memberships` with team/driver foreign keys, required start date, optional end date/role/notes, date checks, date indexes, and an expression unique index that rejects only an exact duplicate period (including a NULL end date).
- `membership_repository`/`membership_service` create, list, update, and end periods. Current-team roster queries exclude rows with an end date unless historical rows are requested.
- The service verifies team/driver references, rejects a current membership for an archived driver, and preserves prior periods on rejoin.
- Tests: `test_membership_repository.c` and `test_reference_services.c` cover periods, ending, rejoin, duplicates, dates, invalid references, and team scoping.
