# 3.2 — Add driver profile records

**Status:** Implemented (2026-11-24)  
**Goal:** Store user-entered driver identity separately from a driver's time-bounded relationship with a team.

## Proposed scope decision

Treat a driver as a shared person identity in the local database and represent team affiliation in the separate membership table from 3.3. Keep the driver profile minimal: required display name, optional short/display name and notes, archive state, and system timestamps. Do not require nationality, birth date, or other personal information. The People tab defaults to drivers linked to the active team; any cross-team directory must be an explicit all-teams view.

- Contracts, salaries, driver ability ratings, and generated driver data are out of scope.
