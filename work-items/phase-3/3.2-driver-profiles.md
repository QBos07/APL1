# 3.2 — Add driver profile records

**Status:** Not started  
**Goal:** Store user-entered driver identity separately from a driver's time-bounded relationship with a team.

## Proposed scope decision

Treat a driver as a shared person identity in the local database and represent team affiliation in the separate membership table from 3.3. Keep the driver profile minimal: required display name, optional short/display name and notes, archive state, and system timestamps. Do not require nationality, birth date, or other personal information. The People tab defaults to drivers linked to the active team; any cross-team directory must be an explicit all-teams view.

## Work list

- [ ] Confirm the shared-identity versus team-owned-profile decision before migration work.
- [ ] Add a migration for the driver profile table with stable ID, required name, optional fields, archive state, and timestamps.
- [ ] Add repository create/list/get/update/archive methods; allow active-team views to filter through memberships once 3.3 exists.
- [ ] Add domain validation for trimmed, non-empty display names and supported text lengths.
- [ ] Define duplicate-name handling: allow identical display names because names are not identities; use IDs to disambiguate.
- [ ] Add unit tests for profile normalization and integration tests for CRUD, archiving, duplicate display names, and stable IDs.
- [ ] Ensure migration inserts no sample drivers.

## Acceptance checks

- [ ] A driver record contains only fields the user supplied plus system metadata.
- [ ] Driver identity is stable across rename and can be linked to multiple historical team memberships.
- [ ] Duplicate display names do not overwrite or merge profiles.
- [ ] Archived drivers remain available in historical membership/outcome references but are excluded from default active pickers.
- [ ] No team roster relationship is stored only as a mutable driver name.

## Dependencies / boundaries

- Depends on the Phase 2 migration/repository conventions.
- Team-specific association is [3.3](3.3-team-driver-membership.md); People UI is [3.8](3.8-people-views.md).
- Contracts, salaries, driver ability ratings, and generated driver data are out of scope.
