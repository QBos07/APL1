# 3.8 — Build People views for drivers and team membership

**Status:** Implemented (2026-11-24)  
**Goal:** Let the user create and maintain driver profiles and dated team affiliations through the People tab.

## Work list

- [x] Build a People list in the main body, defaulting to drivers associated with the active team; clearly label any explicit all-teams view.
- [x] Show display name and known membership state without inferring a seat, contract, ability, or nationality.
- [x] Add driver detail with profile fields and chronological team membership periods.
- [x] Use interactive dialogs for add/edit/archive driver and add/end membership operations.
- [x] Preserve list selection/filter state when opening detail or closing a dialog.
- [x] Offer create/select-driver behavior when adding membership; never create a duplicate profile silently.
- [x] Include command affordances/links for driver commands to be completed with [3.12](3.12-reference-commands.md).
- [x] Add screen-state tests and update the TUI smoke test with a user-entered driver/membership workflow.

## Acceptance checks

- [x] The People tab shows only records in the chosen active-team scope by default.
- [x] A driver profile with no membership is distinguishable from an active team member.
- [x] Membership start/end dates and history are visible; ending membership does not erase it.
- [x] Forms preserve user input after validation errors and explicit Cancel performs no write.
- [x] User can create a driver and add a team membership without any automatically supplied identity/date data.
- [x] Keyboard, mouse, and command handoff use the same use cases.

## Dependencies / boundaries

- Depends on [3.2](3.2-driver-profiles.md), [3.3](3.3-team-driver-membership.md), Phase 2 dialogs/layout redesign (2.19, 2.23), and active-team context.
- Contracts, salaries, driver stats, and race outcomes are deferred.

## Implementation notes (2026-11-24)

- The People tab defaults to drivers linked to the active team; `A` toggles an explicit all-teams directory. Rows show current, historical-only, or no team membership so an unaffiliated profile is distinguishable.
- Driver detail shows profile fields and chronological team membership periods. Create/edit/archive driver and add/end membership use interactive dialogs. Membership add requires an explicit driver context; commands with duplicate names open an explicit choice.
- Commands `driver list|new|show` and `membership add|end` route through the same services. The TUI smoke test covers driver creation and membership entry.
