# 3.8 — Build People views for drivers and team membership

**Status:** Not started  
**Goal:** Let the user create and maintain driver profiles and dated team affiliations through the People tab.

## Work list

- [ ] Build a People list in the main body, defaulting to drivers associated with the active team; clearly label any explicit all-teams view.
- [ ] Show display name and known membership state without inferring a seat, contract, ability, or nationality.
- [ ] Add driver detail with profile fields and chronological team membership periods.
- [ ] Use interactive dialogs for add/edit/archive driver and add/end membership operations.
- [ ] Preserve list selection/filter state when opening detail or closing a dialog.
- [ ] Offer create/select-driver behavior when adding membership; never create a duplicate profile silently.
- [ ] Include command affordances/links for driver commands to be completed with [3.12](3.12-reference-commands.md).
- [ ] Add screen-state tests and update the TUI smoke test with a user-entered driver/membership workflow.

## Acceptance checks

- [ ] The People tab shows only records in the chosen active-team scope by default.
- [ ] A driver profile with no membership is distinguishable from an active team member.
- [ ] Membership start/end dates and history are visible; ending membership does not erase it.
- [ ] Forms preserve user input after validation errors and explicit Cancel performs no write.
- [ ] User can create a driver and add a team membership without any automatically supplied identity/date data.
- [ ] Keyboard, mouse, and command handoff use the same use cases.

## Dependencies / boundaries

- Depends on [3.2](3.2-driver-profiles.md), [3.3](3.3-team-driver-membership.md), Phase 2 dialogs/layout redesign (2.19, 2.23), and active-team context.
- Contracts, salaries, driver stats, and race outcomes are deferred.
