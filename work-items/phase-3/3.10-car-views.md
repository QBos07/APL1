# 3.10 — Build car/chassis reference views

**Status:** Implemented (2026-11-24)  
**Goal:** Let the user maintain the team's cars/chassis as reference records for later development and parts features.

## Work list

- [x] Add a Cars/Chassis sub-view under the Teams tab, linked from team detail and future part/development selectors.
- [x] List only the active team's cars by default; provide explicit archived access.
- [x] Add detail and interactive create/edit/archive dialogs for identifier, optional chassis ID, and notes.
- [x] Use 3.4 validation and repository operations; keep chassis and car labels user-entered.
- [x] Preserve existing references on rename/archive using stable car IDs.
- [x] Add command handoff for `:car` actions through [3.12](3.12-reference-commands.md).
- [x] Test empty, duplicate, archived, and cross-team display states.

## Acceptance checks

- [x] A team can have zero cars; no car is created automatically.
- [x] A car can be created with only the required user-entered identifier.
- [x] Rename/archive preserves the stable ID and historical links.
- [x] Archived cars are hidden from current selectors by default but available to historical views.
- [x] Car records from another team do not appear in the active team's default view.
- [x] Forms work with keyboard and mouse and preserve values on validation error.

## Dependencies / boundaries

- Depends on [3.4](3.4-car-records.md), Phase 2 dialog/layout redesign (2.16, 2.23), and team context.
- No part inventory or performance/specification fields are added here.

## Implementation notes (2026-11-24)

- Cars/chassis are reachable from team detail (`c`) and commands. Lists default to the active team and hide archived rows unless explicitly included.
- Detail and create/edit/archive dialogs use the 3.4 service and preserve stable IDs. No parts/inventory or performance fields are added.
