# 3.10 — Build car/chassis reference views

**Status:** Not started  
**Goal:** Let the user maintain the team's cars/chassis as reference records for later development and parts features.

## Work list

- [ ] Add a Cars/Chassis sub-view under the Teams tab, linked from team detail and future part/development selectors.
- [ ] List only the active team's cars by default; provide explicit archived access.
- [ ] Add detail and interactive create/edit/archive dialogs for identifier, optional chassis ID, and notes.
- [ ] Use 3.4 validation and repository operations; keep chassis and car labels user-entered.
- [ ] Preserve existing references on rename/archive using stable car IDs.
- [ ] Add command handoff for `:car` actions through [3.12](3.12-reference-commands.md).
- [ ] Test empty, duplicate, archived, and cross-team display states.

## Acceptance checks

- [ ] A team can have zero cars; no car is created automatically.
- [ ] A car can be created with only the required user-entered identifier.
- [ ] Rename/archive preserves the stable ID and historical links.
- [ ] Archived cars are hidden from current selectors by default but available to historical views.
- [ ] Car records from another team do not appear in the active team's default view.
- [ ] Forms work with keyboard and mouse and preserve values on validation error.

## Dependencies / boundaries

- Depends on [3.4](3.4-car-records.md), Phase 2 dialog/layout redesign (2.16, 2.23), and team context.
- No part inventory or performance/specification fields are added here.
