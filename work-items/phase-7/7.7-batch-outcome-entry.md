# 7.7 — Add batch outcome-entry operation

**Status:** Planned  
**Goal:** Enter outcomes for multiple drivers in one all-or-none operation.

## Work list

- [ ] Define batch input and per-row validation/error reporting.
- [ ] Validate all targets, duplicates, references, and supplied values before commit.
- [ ] Persist the batch atomically through the same outcome rules as single entry.
- [ ] Test invalid-row rollback, duplicate rows, and transaction failure.

## Acceptance checks

- [ ] One invalid row leaves every outcome in the batch unchanged.
- [ ] Duplicate driver/session targets within a batch are identified explicitly.
- [ ] Missing fields remain missing and valid rows use the same validation as single entry.

## Dependencies / boundaries

- Depends on [7.5](7.5-driver-outcome-schema-repository.md), [7.6](7.6-outcome-validation-save-use-case.md), and transaction infrastructure.
- Does not require every result field for each row.
