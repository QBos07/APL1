# 7.5 — Add driver-outcome schema and repository

**Status:** Planned  
**Goal:** Persist only manually entered outcome values with stable driver, event, and session links.

## Work list

- [ ] Add outcome storage linked to a driver, event, and session, with fields defined by [7.4](7.4-result-field-set.md).
- [ ] Add migration and repository create/read/list/update operations.
- [ ] Preserve nullable/absent values as missing rather than filling defaults.
- [ ] Enforce team consistency across driver, event, and session links.
- [ ] Add migration, repository, missing-value, and team-isolation tests.

## Acceptance checks

- [ ] Outcomes cannot refer across teams or to a session outside the linked event.
- [ ] Stored values round-trip exactly, including missing optional values.
- [ ] No generated result or inferred outcome is stored.

## Dependencies / boundaries

- Depends on [7.1](7.1-event-schema-repository.md), [7.2](7.2-session-schema-repository.md), Phase 3 driver records, [7.4](7.4-result-field-set.md), and migration foundations.
