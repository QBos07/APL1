# 7.6 — Add outcome validation and save use case

**Status:** Planned  
**Goal:** Validate and save one driver’s manually entered outcome without inventing missing values.

## Work list

- [ ] Validate event/session/driver scope and each supplied result field.
- [ ] Define and implement explicit behavior for an existing driver/session outcome (edit, replace, or report duplicate).
- [ ] Save through a shared application operation usable by both forms and commands.
- [ ] Keep omitted optional fields missing and distinguish them from explicit values.
- [ ] Test valid, invalid, duplicate, and failed-save cases.

## Acceptance checks

- [ ] Duplicate targets are handled explicitly and never silently create conflicting records.
- [ ] Invalid input leaves persisted data unchanged.
- [ ] Omitted values remain missing; no zero, DNF, or other default is inferred.

## Dependencies / boundaries

- Depends on [7.4](7.4-result-field-set.md), [7.5](7.5-driver-outcome-schema-repository.md), Phase 3 driver services, and shared transaction/use-case patterns.
