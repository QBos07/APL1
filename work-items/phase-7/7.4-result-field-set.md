# 7.4 — Decide and document the initial result-field set

**Status:** Implemented

**Goal:** Define a small, explicit set of manually entered outcome fields and their missing-value semantics.

## Work list

- [x] Review MVP requirements and choose initial outcome fields and types.
- [x] Document field meaning, validation, units/format, and whether each is optional.
- [x] Specify missing versus entered zero/false/text semantics for every field.
- [x] Keep the model extensible enough for later needs without implementing configurable custom fields.

## Acceptance checks

- [x] Every initial field has an unambiguous meaning and validation rule.
- [x] Missing values remain distinguishable from explicit values.
- [x] No field implies a scoring system, simulation, or inferred result.

## Dependencies / boundaries

- Informs [7.5](7.5-driver-outcome-schema-repository.md), [7.6](7.6-outcome-validation-save-use-case.md), and [7.11](7.11-recorded-value-summaries.md).
- Custom result fields and points/scoring systems are out of scope.
