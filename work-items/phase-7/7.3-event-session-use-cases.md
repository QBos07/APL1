# 7.3 — Add event/session create and edit use cases

**Status:** Planned  
**Goal:** Apply consistent validation and history-preserving operations to event and session changes.

## Work list

- [ ] Add create/edit use cases for events and sessions.
- [ ] Validate required fields and team/season/event references before persistence.
- [ ] Preserve stable identity and existing outcome links when labels/details are edited.
- [ ] Define deletion/archive behavior so referenced history cannot be silently lost.
- [ ] Test invalid references, edits, and failed writes.

## Acceptance checks

- [ ] Invalid or cross-team references are rejected without partial writes.
- [ ] Editing an event/session does not rewrite or discard linked outcomes.
- [ ] History is preserved; destructive removal of referenced records is prevented or explicitly handled.

## Dependencies / boundaries

- Depends on [7.1](7.1-event-schema-repository.md), [7.2](7.2-session-schema-repository.md), and shared use-case transaction conventions.
