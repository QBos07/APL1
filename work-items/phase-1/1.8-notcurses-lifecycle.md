# 1.8 — Own the Notcurses initialize/stop lifecycle

**Status:** Not started  
**Goal:** Give the TUI a single clear owner for Notcurses startup and shutdown, including partial-startup failure.

## Work list

- [ ] Add a small TUI lifecycle module that initializes Notcurses Core and returns an explicit failure if initialization fails.
- [ ] Define which object owns the `struct notcurses` pointer and ensure it is stopped exactly once.
- [ ] Handle partial startup so a failed initialization does not call stop on an invalid handle.
- [ ] Route normal exit and error exit through the same cleanup path.
- [ ] Keep screen drawing/input logic out of the lifecycle module.
- [ ] Add a manual smoke-check note for running in a real terminal and exiting cleanly.

## Acceptance checks

- [ ] The app can initialize and stop Notcurses once in a supported interactive terminal.
- [ ] Initialization failure returns a useful application error and does not crash during cleanup.
- [ ] Normal exit restores the terminal to a usable state.
- [ ] Lifecycle ownership is explicit; no duplicate stop or leaked Notcurses context exists on the tested paths.
- [ ] Database/application modules do not initialize or stop Notcurses themselves.

## Dependencies / boundaries

- Depends on [1.1](1.1-application-error-type.md) and [0.3](../phase-0/0.3-source-layout.md).
- This task does not implement menus, forms, mouse interaction, or team screens.
