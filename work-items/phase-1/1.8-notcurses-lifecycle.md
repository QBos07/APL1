# 1.8 — Own the Notcurses initialize/stop lifecycle

**Status:** Done  
**Goal:** Give the TUI a single clear owner for Notcurses startup and shutdown, including partial-startup failure.

## Implementation notes (2026-11-24)

- Module: `src/tui/lifecycle.h` / `src/tui/lifecycle.c` (static library `apl_tui`,
  the only project module that initializes Notcurses).
- Ownership: an `apl_tui` value owns exactly one `struct notcurses` context
  (`tui->notcurses`); `apl_tui_start` creates it, `apl_tui_stop` releases it and
  clears the pointer, so each successful stop runs exactly once.
- Partial startup: when `notcurses_init` returns NULL the value stays
  uninitialized, the caller receives `APL_ERR_TUI_INIT` with an actionable message,
  and no stop call is needed — `apl_tui_stop` on a NULL handle is a documented
  no-op, so a failed startup cannot crash during cleanup.
- Normal exit and error exit route through the same `apl_tui_stop`; database and
  application modules never initialize or stop Notcurses themselves.
- Dependency note: `cmake/NotcursesDependency.cmake` now prefers the full
  `notcurses` pkg-config module before `notcurses-core`, because on this system
  `notcurses_init` is only exported by the full library (`libnotcurses.so`);
  `notcurses-core` remains the fallback.
- Tests: TUI lifecycle contracts that need no terminal live in the separate
  `apl1_tui_tests` executable (CTest `apl1_tui_tests`), the only test target linking
  Notcurses modules: safe stop on uninitialized/NULL contexts, and a start-failure
  path that needs no stop. Conventions updated in CONTRIBUTING.md accordingly.

Interactive lifecycle verification is recorded with the entry-point smoke run in
[1.9](1.9-empty-tui-shell.md), which exercises startup, resize, exit, and terminal
restoration together. Its original one-off pty driver and raw log were kept under
`/tmp` and are not reproducible from the repository; a checked-in smoke harness is
tracked in [foundation hardening](../foundation-hardening/FH-01-reproducible-tui-smoke.md).
