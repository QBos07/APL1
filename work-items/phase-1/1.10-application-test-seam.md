# 1.10 — Separate application lifecycle from interactive terminal input

**Status:** Not started  
**Goal:** Allow startup/shutdown and database coordination to be tested without creating a fake terminal session.

## Work list

- [ ] Separate application initialization/cleanup from the interactive TUI event loop.
- [ ] Make application initialization accept explicit configuration, including a temporary database path for tests.
- [ ] Ensure initialization composes database open, foreign-key setup, and migrations in the documented order.
- [ ] Ensure a failure at any initialization step closes already-open resources.
- [ ] Add tests for successful app initialization/cleanup and one or more failure paths.
- [ ] Keep the tests independent of a real Notcurses terminal; test the TUI lifecycle separately/manual-smoke-check it.

## Acceptance checks

- [ ] Application startup can be exercised by a test using a temporary SQLite database and no terminal input.
- [ ] Successful initialization reaches the expected schema version and cleanup closes the database.
- [ ] A database/migration failure is returned to the caller and does not leak an opened connection.
- [ ] The interactive main loop remains a thin composition of application setup, TUI run, and cleanup.
- [ ] No production startup path silently switches to a different database after an error.

- Depends on [1.2](1.2-database-connection.md), [1.3](1.3-database-path.md), [1.4](1.4-foreign-keys.md), [1.5](1.5-migration-runner.md), [1.6](1.6-initial-migration.md), [1.7](1.7-migration-rollback.md), and [1.8](1.8-notcurses-lifecycle.md).
