# 1.10 — Separate application lifecycle from interactive terminal input

**Status:** Done  
**Goal:** Allow startup/shutdown and database coordination to be tested without creating a fake terminal session.

## Implementation notes (2026-11-24)

- New `src/app` module (`apl_app`) owns the non-interactive side of startup:
  `apl_app_start` composes database path resolution (1.3), database open with
  foreign-key verification (1.2/1.4), and migration (1.5/1.6) in that
  documented order; `apl_app_stop` closes the connection (safe on an
  uninitialized/already-stopped value).
- `apl_app_config` carries explicit configuration, including a temporary
  database path for tests; zero-initialization selects the environment-derived
  default path from the 1.3 policy.
- Failure contract: a failure at any initialization step closes every
  resource opened so far (a migration failure closes the connection) and the
  error is returned to the caller; no path silently switches to a different
  database after an error.
- `src/main.c` is a thin composition: TUI start (1.8) → application start →
  shell run (1.9) → `apl_app_stop` → `apl_tui_stop`. The TUI is started
  first, so a launch without a usable interactive terminal fails cleanly
  before any database file is created.
- `apl_tui_start` now requires an interactive terminal (stdin and stdout both
  terminal devices) and reports APL_ERR_TUI_INIT otherwise; `apl_tui_shell_run`
  treats input EOF (`NCKEY_EOF`) as input unavailability (APL_ERR_TUI_INPUT)
  instead of spinning. Both harden the 1.8/1.9 lifecycle against the
  non-interactive launch failure this work item exposed.

## Verification record (2026-11-24)

- `ctest --test-dir /tmp/apl1-build --output-on-failure`: 2/2 CTest tests pass
  (`apl1_unit_tests` 40/40 Criterion tests, `apl1_tui_tests` 5/5).
- New tests `tests/integration/test_app_lifecycle.c` (terminal-free):
  - start/stop with a temporary database reaches schema version 1, the
    connection is closed by cleanup, and the database file survives cleanup.
  - an explicit path whose parent directory does not exist fails with
    APL_ERR_DB_OPEN and leaks no opened connection.
  - a database at schema version 99 (newer than the application) fails with
    APL_ERR_DB_SCHEMA_TOO_NEW and leaks no opened connection.
  - stop on a NULL/uninitialized app is a no-op.
- Interactive pty smoke test (1.9-style, with terminal-query emulation):
  initial frame, resize redraw, `q`-exit with code 0, terminal restored, and
  the database created at the default location with schema version 1.
- Non-interactive launch (`apl1 < /dev/null`): exits with code 1 and reports
  "apl1: Notcurses initialization failed; a usable interactive terminal is
  required" on stderr; no database file is created.
