## Implementation notes (2026-11-24)

- `src/db/migrations_list.c` holds the compiled-in migration list registered with the
  runner from 1.5; `apl_db_migrate`/`apl_db_migrations_list` are the production entry
  points declared in `src/db/migrations.h`.
- Version 1 is deliberately an empty baseline: its SQL is comments only. No teams,
  drivers, seasons, events, financial entries, or demo rows are created — the only
  table after migration is the migration infrastructure table `apl_schema_migrations`.
  Feature schemas are documented (in migrations_list.c and here) to arrive as later
  ordered migrations alongside their feature work.
- Tests: `tests/integration/test_db_initial_migration.c` — a new database is marked
  version 1 with exactly one version record; the resulting schema contains only
  `apl_schema_migrations` and no domain/sample records; a second `apl_db_migrate` run
  is a no-op (version and record count unchanged).
