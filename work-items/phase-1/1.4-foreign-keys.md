# 1.4 — Enable and verify SQLite foreign keys

**Status:** Done  
**Goal:** Ensure every application database connection enforces declared foreign-key constraints.

## Implementation notes (2026-11-24)

- `apl_db_open` is the single connection-creation path, and it now runs an
  initialization routine immediately after `sqlite3_open_v2`, before any
  application query/write: it executes `PRAGMA foreign_keys = ON;` and then
  reads `PRAGMA foreign_keys;` back through a prepared statement, requiring
  the value `1`.
- If enforcement cannot be enabled or verified, the connection reports
  `APL_ERR_DB_FOREIGN_KEYS` with a useful message and the partially initialized
  handle is released (`sqlite3_close` + `connection->handle = NULL`) instead of
  continuing silently.
- Tests: `tests/integration/test_db_foreign_keys.c` — a new connection reports
  enforcement enabled through the API, and a parent/child schema rejects an
  invalid child insert with `SQLITE_CONSTRAINT` while a valid insert succeeds
  once the parent exists. Test schema/data are cleaned by removing the
  temporary database file itself.
