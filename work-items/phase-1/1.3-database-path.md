# 1.3 — Define and implement database-path resolution

**Status:** Not started  
**Goal:** Make it predictable which local SQLite file the application opens, while allowing isolated paths in tests and development.

## Proposed v1 policy

1. A path explicitly supplied through application configuration takes precedence.
2. Otherwise, use `$XDG_DATA_HOME/apl1/apl1.sqlite3` when `XDG_DATA_HOME` is set and usable.
3. Otherwise, use `$HOME/.local/share/apl1/apl1.sqlite3`.
4. If neither explicit configuration nor a usable home/data directory exists, fail with a clear error rather than silently creating a database in the current working directory.
5. Create the application data directory when needed. Tests pass a temporary explicit path and do not change process-global environment variables.

Confirm or amend this policy before implementation and record the final choice here.

## Confirmed policy and implementation notes (2026-11-24)

The proposed policy is confirmed as documented in `src/db/path.h`:
explicit path → absolute `$XDG_DATA_HOME/apl1/apl1.sqlite3` → absolute
`$HOME/.local/share/apl1/apl1.sqlite3` → clear failure (never the current
working directory). Relative XDG/HOME values violate the XDG spec and are
ignored (fall through to the next candidate). Directory creation happens only
through `apl_db_ensure_parent_directory` (mkdir -p of every component before
the final file component) and is used for environment-derived defaults;
explicit paths must have a usable parent directory already so typos are not
masked. Paths are rejected (not truncated) above `APL_DB_PATH_MAX` (4096).

- Module: `src/db/path.h` / `src/db/path.c` in library `apl_db`.
- Testable core: `apl_db_resolve_path_ex(explicit, xdg_data_home, home, ...)` never
  touches process-global state; the production wrapper `apl_db_resolve_path` only
  adds `getenv`.
- Tests: `tests/integration/test_db_path.c` — explicit override, absolute XDG,
  relative-XDG fallthrough to HOME, HOME fallback, empty/missing environment
  failure message, buffer-too-small rejection, nested parent-directory creation,
  file-collision failure, empty/NULL path rejection.
- Test contract: `apl_db_resolve_path_ex` is the tested deterministic resolver;
  it receives environment values as arguments. `apl_db_resolve_path` is only a
  thin `getenv` adapter and is intentionally not tested by changing process-global
  environment variables. This boundary is part of the module documentation.
