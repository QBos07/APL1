# 1.2 — Add a SQLite connection lifecycle wrapper

**Status:** Done  
**Goal:** Centralize opening and closing SQLite connections and translate connection failures into useful application errors.

## Implementation notes (2026-11-24)

- Module: `src/db/connection.h` / `src/db/connection.c` (static library `apl_db`, linking `apl_core` and SQLite; the header includes `<sqlite3.h>` because callers borrow the handle).
- `apl_db_connection` owns exactly one `sqlite3*` handle; it is zero-initialized by callers before `apl_db_open`.
- `apl_db_open(path)` uses `sqlite3_open_v2` with `SQLITE_OPEN_READWRITE | SQLITE_OPEN_CREATE` and the default threading model — documented decision for this single-process local application (no FULLMUTEX/URI/shared-cache flags).
- On open failure the SQLite message is captured before `sqlite3_close` releases the partially created handle; `connection->handle` is NULL afterwards and the error is `APL_ERR_DB_OPEN` with context `'cannot open database '<path>': <sqlite message>'`.
- `apl_db_close` is a documented no-op on an uninitialized/already-closed connection (NULL handle), making cleanup paths safe. Path resolution is deliberately NOT in this module (see 1.3); foreign-key initialization is deliberately NOT here (see 1.4).
- Shared integration-test helper: `tests/integration/test_support.h/.c` creates a unique `mkdtemp` directory per test and removes every file in it afterwards (a test fails if it leaks files).
- Tests: `tests/integration/test_db_connection.c` — open + trivial table create/read, close/reopen persistence, safe close on uninitialized and repeated close, invalid path (missing parent dir) failing with useful message and no leaked handle, NULL/empty path rejected.
