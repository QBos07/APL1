# 1.2 — Add a SQLite connection lifecycle wrapper

**Status:** Not started  
**Goal:** Centralize opening and closing SQLite connections and translate connection failures into useful application errors.

## Work list

- [ ] Add a small database connection type that owns one `sqlite3*` handle.
- [ ] Implement open using a caller-supplied path; do not resolve default paths in this module.
- [ ] Implement close and make the closed/uninitialized state safe to clean up.
- [ ] On open failure, capture a useful SQLite message and release any partially created handle.
- [ ] Decide/document the minimum open flags needed for this local application.
- [ ] Add temporary-database tests for open, close, reopen, and an invalid/unwritable path.

## Acceptance checks

- [ ] A successfully opened connection can create and read a trivial test table.
- [ ] Closing a connection releases the handle; closing an uninitialized/already-closed wrapper is safe or explicitly rejected by a documented contract.
- [ ] An invalid path returns an application error with useful context and no leaked handle.
- [ ] Database code does not call Notcurses or print directly to the terminal.
- [ ] Tests use temporary paths and leave no project database behind.

## Dependencies / boundaries

- Depends on [1.1](1.1-application-error-type.md).
- Foreign-key initialization is a separate task ([1.4](1.4-foreign-keys.md)); default path selection is [1.3](1.3-database-path.md).
