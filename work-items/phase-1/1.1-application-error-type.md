# 1.1 — Add an application error type

**Status:** Done  
**Goal:** Give application and business-operation code a small way to report failures without depending on Notcurses or exposing SQLite-specific errors to every caller.

## Implementation notes (2026-11-24)

- Module: `src/core/error.h` / `src/core/error.c` (built as static library `apl_core`, linked by `apl1` and `apl1_tests`). Placed in the `src/core/` directory confirmed in 0.3 so every layer can depend on it without a layering inversion.
- `apl_status` is a stable enum of application codes (`APL_OK = 0`, `APL_ERR_*` appended only at the end, never renumbered).
- `apl_error` is a caller-owned value: status code plus a fixed `APL_ERROR_MESSAGE_MAX` (256) message buffer. Ownership is documented in the header — the struct owns its buffer, no dynamic allocation, so there is nothing to free and nothing can leak.
- API: `apl_error_init` (success state), `apl_error_clear` (reset), `apl_error_set`/`apl_error_setv` (printf-style message, format-checked attribute, truncation-safe), `apl_error_code`, `apl_error_message`, `apl_error_is_success`, and `apl_status_string`. Getter/setter NULL defenses are documented.
- Fallible-function convention: functions return `apl_status` and may take an optional `apl_error *` that is written only on failure (implemented by later tasks). No global last-error state.
- Tests: `tests/unit/test_error.c` — success initialization, failure capture of code + formatted message, clear reset, oversize-message truncation and termination, NULL defense, stable status strings.
