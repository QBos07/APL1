# 1.9 — Replace the placeholder with an empty TUI shell

**Status:** Done  
**Goal:** Prove the application can display a minimal Notcurses screen and exit cleanly before adding domain screens.

## Implementation notes (2026-11-24)

- `src/main.c` no longer prints "Hello, World!": it starts the TUI through
  `apl_tui_start` (1.8), runs the scaffold shell `apl_tui_shell_run`, and
  always stops through `apl_tui_stop` (1.8) on both the success and failure
  paths.
- `src/tui/shell.{h,c}` draws three lines: the application name, an honest
  empty state ("No teams have been added yet. Management screens arrive in
  later phases."), and the visible exit affordance "Press q to quit.". No
  team, record, or generated business data exists on screen.
- The loop redraws from the current plane dimensions after every key,
  including the synthesized `NCKEY_RESIZE`, so a smaller or larger terminal
  never draws outside the available area (`draw_line` clamps to the plane).
- Any terminal error (render failure, input stream EOF) returns a
  `APL_ERR_TUI_*` status to `main`, which stops the TUI and reports cleanly
  on stderr — no hang, no corrupted terminal state.
- Screen shutdown is routed through `apl_tui_stop` only; the shell module
  never touches the Notcurses context beyond drawing and input.

## Verification record (2026-11-24)

- `ctest --test-dir /tmp/apl1-build --output-on-failure`: 2/2 CTest tests
  pass (`apl1_unit_tests` 36/36 Criterion tests, `apl1_tui_tests` 5/5).
- Interactive pty smoke test (Python pty driver that emulates the terminal
  side of the query/response handshake — a raw pty never answers notcurses'
  DA1/CPR/OSC queries and a real terminal always does, so the driver replies
  to them like a real terminal would):
  - initial 24x80 frame contains the title, the honest empty state, and
    "Press q to quit."; no sample/team data on screen.
  - resize to 40x120 + SIGWINCH: shell redraws the full screen at the new
    size without crashing and without stale content.
  - pressing `q` exits with code 0.
  - after exit the pty line discipline is restored (ECHO and ICANON back on).
  - raw terminal output captured in `/tmp/apl1-pty-log.txt` (3 renders).
- Non-interactive launch (no terminal): `apl1` exits immediately with
  "apl1: Notcurses initialization failed; a usable interactive terminal is
  required" (covered by the 1.8 start-failure test).
