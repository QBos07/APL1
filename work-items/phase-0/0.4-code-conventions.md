# 0.4 — Document small-project code conventions

**Status:** Done  
**Goal:** Give contributors a short, consistent set of C and test conventions that match the existing C23/CMake setup.

## Summary

Conventions are documented in [CONTRIBUTING.md](../../CONTRIBUTING.md) and linked
from the README's contributing section. They cover: C23 with extensions disabled and
warnings as errors (`-Wall -Wextra -pedantic -Werror -pedantic-errors`), the confirmed
module layout and where a module's `.c`/`.h` files belong, `apl_`/module-prefixed
snake-case naming, include-guard style, the `apl_status`/`apl_error` error convention,
`_POSIX_C_SOURCE 200809L` in files calling POSIX APIs, and how Criterion tests are
organized after 0.2 (`tests/unit/test_<module>.c`, suite named after the module,
single `apl1_tests` executable registered as CTest `apl1_unit_tests`). They state that
business-logic tests must not require an interactive Notcurses terminal and that
integration tests use temporary databases.
