# 0.3 — Confirm the initial source layout

**Status:** Done  
**Goal:** Agree on a small C project layout that separates business rules, SQLite persistence, application coordination, and Notcurses presentation.

## Confirmed layout (2026-11-24)

The proposed layout is confirmed with one amendment: a fifth source directory,
`src/core/`, holds shared foundation types with no dependencies on other project
modules. Its first resident is the application error type from [1.1](../phase-1/1.1-application-error-type.md),
which must be includable by `app`, `db`, `domain`, and `tui` alike; without it,
`db`/`domain` would have to depend on `app`, an avoidable layering inversion.

```text
src/
  core/      shared foundation types, no project dependencies (application error type)
  app/       application/use-case coordination (startup/shutdown composition)
  db/        SQLite connection, path resolution, migrations, repositories
  domain/    business rules and domain types
  tui/       Notcurses lifecycle, screens, input handling
tests/
  unit/        pure business logic and utility tests
  integration/ SQLite-backed tests with temporary databases
  tui/         TUI lifecycle tests that never require an interactive terminal
```

- `src/main.c` remains the small composition/startup entry point.
- `src/tui` is the only module that may initialize Notcurses; `src/db` is the only module that executes SQL.
- CMake target source lists stay explicit per module (no globbing); modules are built as small static libraries linked by the `apl1` executable and by the test executable(s) that need them.
- Directory purpose notes live in a short `README.md` inside each directory.
