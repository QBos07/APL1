# 2.1 — Add the main navigation model

**Status:** Not started  
**Goal:** Represent the current TUI section/screen and navigation transitions independently from Notcurses drawing and business data.

## Work list

- [ ] Define the initial section IDs: Overview, Teams, and placeholders for the later areas named in `REQUIREMENTS.md`.
- [ ] Define a small navigation state for current section/screen and the minimum back-navigation context needed by the shell.
- [ ] Define transitions for opening a section, entering a detail view, and returning to the previous view.
- [ ] Decide what happens when the requested section is not implemented yet (show a clear placeholder, not a blank screen).
- [ ] Keep active-team data separate from navigation state; navigation must not change teams implicitly.
- [ ] Add tests for valid transitions, back behavior, and unknown/unavailable destinations.

## Acceptance checks

- [ ] Navigation state can be created and transitioned in tests without initializing Notcurses.
- [ ] The current section and screen are unambiguous after every transition.
- [ ] Returning from a detail/placeholder view restores the prior section context.
- [ ] Selecting an unavailable feature shows an explicit placeholder state and does not mutate data.
- [ ] The navigation model contains no SQL, team repository calls, or rendering code.

## Dependencies / boundaries

- Depends on [2.0.1](2.0.1-tui-layout-resize-decision.md) and completed Phase 1 app/TUI lifecycle.
- This task defines state and transitions only; drawing the shared frame is [2.2](2.2-shared-screen-frame.md).
