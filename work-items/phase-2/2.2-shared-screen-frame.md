# 2.2 — Draw the shared screen frame

**Status:** Not started  
**Goal:** Establish one consistent visual frame that all Phase 2 screens can fill.

## Work list

- [ ] Add the persistent section title/navigation region using the plane/layout decision from [2.0.1](2.0.1-tui-layout-resize-decision.md).
- [ ] Show active-team context, including an explicit “no active team” state before team creation.
- [ ] Add a message/status region for save confirmation, validation, errors, and contextual hints.
- [ ] Draw a useful small-terminal state instead of clipping essential status or actions.
- [ ] Recompute region dimensions and redraw the complete frame on resize.
- [ ] Keep frame rendering driven by view state; do not make the drawing code query SQLite or mutate app state.
- [ ] Add terminal-free tests for layout calculations and a manual/smoke check for actual rendering.

## Acceptance checks

- [ ] The frame displays section and team context consistently, including the no-team state.
- [ ] Status messages are visible and do not overwrite the main screen content.
- [ ] Resize causes a complete redraw using the decided dedicated-plane model, with no stale content.
- [ ] Layout calculations have tests for normal and constrained dimensions without requiring a terminal.
- [ ] Rendering has no direct database calls or business-rule decisions.

## Dependencies / boundaries

- Depends on [2.0.1](2.0.1-tui-layout-resize-decision.md), [2.1](2.1-navigation-model.md), and the Phase 1 Notcurses lifecycle.
- Does not implement team list/detail forms or reusable table behavior.
