# 2.6 — Add team repository create/list/get operations

**Status:** Not started  
**Goal:** Provide the first production persistence API for teams, following the Phase 2 repository ownership contract.

## Work list

- [ ] Add a `team` repository module in the agreed source layout.
- [ ] Implement create with bound parameters and return the stable ID of the inserted record.
- [ ] Implement list of active teams and an explicit include-archived option for history/admin views.
- [ ] Implement get-by-ID that can retrieve archived rows when explicitly requested.
- [ ] Keep prepared-statement handles local to repository calls and finalize them on every path.
- [ ] Borrow the connection; do not open/close the application database in the repository.
- [ ] Add SQLite integration tests for create/list/get, ordering, missing IDs, archived filtering, and SQL-special characters in text.

## Acceptance checks

- [ ] Repository operations use parameterized SQL and never concatenate user values into SQL text.
- [ ] Create returns the actual stable ID; list/get return only records in the requested scope.
- [ ] Archived rows are excluded by default and available through an explicit query option.
- [ ] Missing records return a consistent not-found result, not a fabricated empty record.
- [ ] Statements are finalized and connection ownership remains with the caller.
- [ ] Tests use the test-support target and isolated temporary SQLite databases.

## Dependencies / boundaries

- Depends on [2.5](2.5-team-schema.md), [2.0.3](2.0.3-repository-ownership-decision.md), and [FH-05](../foundation-hardening/FH-05-test-support-library.md).
- Do not implement input validation or Notcurses screens in the repository.
