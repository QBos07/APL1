# 2.25 — Add the ex-style command line surface

**Status:** Complete (2026-11-24)  
**Goal:** Provide a Vim-inspired colon command entry surface without requiring Vim's normal-mode keybinding model.

## Work list

- [x] Open command entry on `:` when focus is not inside a text field; provide a visible clickable command affordance as an alternative.
- [x] Draw the prompt in a command overlay/status area while preserving the active tab/body view.
- [x] Support editing the current command, Enter to submit, Escape to cancel, and up/down for current-session command history.
- [x] Show inline completion/usage suggestions without obscuring typed text or current team context.
- [x] Ensure `:` typed into an active form field remains ordinary text.
- [x] Show parse/validation results in the status bar or an interactive dialog as appropriate.
- [x] Add terminal-free command-line state tests and smoke checks for open/cancel/submit.

## Acceptance checks

- [x] The command line is discoverable and opens without losing the underlying screen state.
- [x] Escape cancels the prompt without executing; Enter submits exactly once.
- [x] Text-entry controls still accept a literal colon.
- [x] Command history is session-local and does not become an audit or persistent sensitive-data log.
- [x] Mouse and keyboard can invoke command entry.
- [x] Command failures leave the active view/team unchanged unless the command explicitly requested a change.

## Dependencies / boundaries

- Depends on [2.16](2.16-redesign-layout-geometry.md), [2.21](2.21-status-bar.md), and the mouse/focus policy in [2.0.2](2.0.2-mouse-focus-decision.md).
- Parsing and execution are separate items: [2.26](2.26-command-parser-registry.md) and [2.27](2.27-core-command-actions.md).
