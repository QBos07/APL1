# 2.17 — Add the window-bar dropdown menu model

**Status:** Complete (2026-11-24)  
**Goal:** Model top-bar dropdown contents, focus, and activation independently of rendering.

## Work list

- [x] Define menu groups: **Overview**, **Settings**, **Help**, and **About**.
- [x] Define initial entries: active-team overview and all-teams overview; application/database settings; interaction/command help; About and Version information.
- [x] Represent unavailable future overview pages as explicit disabled/placeholder entries rather than fake reports.
- [x] Add open/close, move focus, activate, and dismiss state transitions for menus.
- [x] Preserve the selected body tab/view while opening and closing menus.
- [x] Add unit tests for menu traversal, wrap behavior, unavailable entries, activation, and dismissal.

## Acceptance checks

- [x] Every menu item has an explicit action or a clearly disabled/placeholder state.
- [x] Opening a dropdown does not change the current team or body view.
- [x] Menu state is testable without Notcurses and has no persistence/business logic.
- [x] About/version values have a documented source of truth; no manually duplicated version strings are introduced.

## Dependencies / boundaries

- Depends on [2.16](2.16-redesign-layout-geometry.md).
- Rendering and mouse/keyboard hit handling are [2.18](2.18-window-menu-rendering.md).
