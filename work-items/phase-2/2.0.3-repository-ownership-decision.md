# 2.0.3 — Define repository, statement, and transaction ownership

**Status:** Not started  
**Goal:** Set a clear persistence boundary before the team schema/repository work begins.

## Proposed ownership contract

- The application owns the database connection lifetime; repositories and use cases borrow it and never close it.
- A repository owns each prepared statement it creates and finalizes it before returning. Statement handles do not escape repository calls.
- Repositories provide parameterized single-operation persistence methods and do not silently begin, commit, or roll back a larger business transaction.
- A use case owns the transaction boundary for a multi-write operation (such as create-team plus settings, or a later replacement workflow). The database layer exposes a small begin/commit/rollback API so use cases do not issue raw transaction SQL.
- A failed operation rolls back before returning; rollback errors must not silently replace the original failure context.
- Production headers are exposed by production targets only; test helpers live in test-only targets and are linked privately.

Confirm or amend this contract before repository implementation.
