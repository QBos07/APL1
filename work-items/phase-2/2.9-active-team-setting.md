# 2.9 — Add a persisted active-team setting

**Status:** Done (2026-11-24)
**Goal:** Persist the selected team by stable ID and recover safely if that team is no longer active.

## Implementation notes (2026-11-24)

- Migration 3 creates the singleton `app_settings` row with a nullable
  `active_team_id` foreign key. No team name is stored as identity.
- `src/db/settings_repository.{h,c}` reads/sets/clears the stable ID and rejects
  missing or archived targets without changing the previous selection.
- `apl_team_service_active` resolves the stored ID; if it is missing/archived,
  it deterministically chooses the oldest-created non-archived team (stable ID
  tie-breaker), persists that ID in the same recovery, and returns
  `APL_ACTIVE_TEAM_FALLBACK` so the UI can explain the switch. Empty databases
  return `APL_ACTIVE_TEAM_NONE`; no row is fabricated.
- Tests: `test_settings_repository.c`, `test_team_service.c` (persistence,
  invalid/archived selection, deterministic fallback), and the relaunch smoke.
