# 2.24 — Move team create/edit/switch flows into dialogs

**Status:** Complete (2026-11-24)  
**Goal:** Make common team actions interactive dialogs while keeping team details and lists in the body.

## Work list

- [x] Convert Create team from a full-screen flow to the form dialog from [2.23](2.23-interactive-form-dialogs.md).
- [x] Convert team rename/edit to a prefilled dialog launched from team detail.
- [x] Convert team selection from a full-page switcher to the dialog launched by the rail/status team control.
- [x] Keep team list/detail management available in the Teams body tab; switching and management remain distinct actions.
- [x] Route each dialog submit through existing team use cases and preserve validation/error behavior.
- [x] On success, close the dialog, update the frame/team state, and show a concise status confirmation.
- [x] Test cancellation, invalid input, duplicate names, active-team switch, archive fallback, and dialog focus restoration.

## Acceptance checks

- [x] Create/edit/switch use the common dialog interaction and same business operations as before.
- [x] A cancelled or invalid dialog performs no write and preserves the appropriate context.
- [x] Successful team creation activates the new team; switching preserves the body tab.
- [x] Renaming preserves team ID; archiving the active team selects the documented fallback.
- [x] Team details/list remain accessible as normal body views.
- [x] No modal action performs direct SQL.
