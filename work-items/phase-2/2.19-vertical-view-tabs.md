# 2.19 — Add the vertical view-tab rail

**Status:** Complete (2026-11-24)  
**Goal:** Make the primary application views a persistent vertical tab list on the left.

## Work list

- [x] Render Overview, Teams, People, Events & Outcomes, Money, Development, Parts, and History as vertically stacked tabs.
- [x] Remove Settings from the primary tab list; expose it through the window-bar Settings menu.
- [x] Show a textual active-tab indicator and a distinct keyboard/mouse focus treatment.
- [x] Route tab activation through the navigation model and render the selected view in the body region.
- [x] Add placeholders for later-phase views without implying that their records exist.
- [x] Support focus transfer among window bar, tab rail, body, status bar, and dialogs.
- [x] Add pure state tests plus smoke coverage for switching tabs and preserving team context.

## Acceptance checks

- [x] All primary views appear in the left vertical rail and activate the matching body view.
- [x] Active tab and focused tab are distinguishable without relying only on color.
- [x] Settings is reachable from the top menu and is not duplicated as a primary tab.
- [x] Switching tabs does not switch teams or modify data.
- [x] Placeholder tabs remain honest and can be reached without a mouse.
- [x] Tab rail reflows or scrolls in compact sizes without losing access to all tabs.

## Dependencies / boundaries

- Depends on [2.16](2.16-redesign-layout-geometry.md), [2.18](2.18-window-menu-rendering.md), and the existing navigation model ([2.1](2.1-navigation-model.md)).


## Verification (2026-11-24)

- `src/tui/navigation` now models eight primary tabs (Settings excluded), with
  full/short labels, tab indexes, wrapping next/previous, and name resolution.
- The shell draws the rail from the 2.16 rectangle, keeps the active tab visible
  through the list viewport, uses textual `*`/`>` active/focus markers, and
  routes keyboard/mouse tab activation through `set_section`.
- `tests/tui/test_tui_navigation.c` covers tab membership, Settings exclusion,
  wrap behavior, short labels, and name resolution. The smoke harness switches
  to People by mouse and back to Teams.
- `ctest --test-dir cmake-build-debug --output-on-failure`: 2/2 tests pass.
