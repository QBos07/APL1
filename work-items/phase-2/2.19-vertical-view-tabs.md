# 2.19 — Add the vertical view-tab rail

**Status:** Not started  
**Goal:** Make the primary application views a persistent vertical tab list on the left.

## Work list

- [ ] Render Overview, Teams, People, Events & Outcomes, Money, Development, Parts, and History as vertically stacked tabs.
- [ ] Remove Settings from the primary tab list; expose it through the window-bar Settings menu.
- [ ] Show a textual active-tab indicator and a distinct keyboard/mouse focus treatment.
- [ ] Route tab activation through the navigation model and render the selected view in the body region.
- [ ] Add placeholders for later-phase views without implying that their records exist.
- [ ] Support focus transfer among window bar, tab rail, body, status bar, and dialogs.
- [ ] Add pure state tests plus smoke coverage for switching tabs and preserving team context.

## Acceptance checks

- [ ] All primary views appear in the left vertical rail and activate the matching body view.
- [ ] Active tab and focused tab are distinguishable without relying only on color.
- [ ] Settings is reachable from the top menu and is not duplicated as a primary tab.
- [ ] Switching tabs does not switch teams or modify data.
- [ ] Placeholder tabs remain honest and can be reached without a mouse.
- [ ] Tab rail reflows or scrolls in compact sizes without losing access to all tabs.

## Dependencies / boundaries

- Depends on [2.16](2.16-redesign-layout-geometry.md), [2.18](2.18-window-menu-rendering.md), and the existing navigation model ([2.1](2.1-navigation-model.md)).
