# 2.14 — Add a team-isolation integration test

**Status:** Done (2026-11-24)
**Goal:** Prove persisted team operations and active-team selection do not leak data across workspaces.

## Implementation notes (2026-11-24)

- `tests/integration/test_team_isolation.c` creates two teams through the public
  service path with distinct notes, renames one, verifies get/list/update scope,
  switches active selection by stable ID, archives one, and verifies the other
  row and active selection are unchanged.
- A stale archived selection is covered by `test_team_service.c` (deterministic
  fallback); the last remaining active team archive attempt is rejected in both
  the isolation test and service tests.
- All setup/writes use public use cases/repositories with the temporary
  database fixture; direct SQL is not used. The test runs in the regular
  `apl1_unit_tests` integration suite.
