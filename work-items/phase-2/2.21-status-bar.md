# 2.21 — Implement the persistent status bar

**Status:** Not started  
**Goal:** Give the bottom row a consistent place for active-team context and concise application feedback.

## Work list

- [ ] Render the status bar across the bottom of the terminal using the new geometry.
- [ ] Show active team and view context, plus the latest success, warning, or error message when one exists.
- [ ] Show a discoverable command hint (for example, `:` for commands) without obscuring the main message.
- [ ] Define message lifetime/replacement rules so a stale success does not hide a later error.
- [ ] Give error/warning/success states distinct color and textual markers.
- [ ] Route status-bar team activation to the same switcher as [2.20](2.20-team-switcher-rail.md); other status text remains informational.
- [ ] Add state tests and verify truncation/wrapping at supported terminal widths.

## Acceptance checks

- [ ] Active-team identity and current feedback remain visible across tabs and dialogs where space permits.
- [ ] The latest error is not silently replaced by an unrelated transient success.
- [ ] Narrow status space uses an explicit compact representation and does not split UTF-8 text incorrectly.
- [ ] Clickable team status region has an equivalent keyboard action and a hit region rebuilt after resize.
- [ ] Message priority/lifetime behavior is deterministic and tested.

## Dependencies / boundaries

- Depends on [2.16](2.16-redesign-layout-geometry.md) and [2.20](2.20-team-switcher-rail.md).
- Long error details still use dialogs; the status bar is not the only error presentation.
