# 2.13 — Build the empty-database welcome flow

**Status:** Not started  
**Goal:** Make first launch understandable and guide the user to enter their own team data.

## Work list

- [ ] Detect the no-team state after migrations and application startup.
- [ ] Show a short welcome stating that the database contains no teams or preloaded F1 data.
- [ ] Offer Create team and Quit as clear actions; do not force immediate data entry.
- [ ] After team creation, show optional next steps (for example, add a driver, create a season, record an opening balance, or add an event) without creating them automatically.
- [ ] On later launches, restore the active team and bypass the first-run welcome when one exists.
- [ ] Handle all-teams-archived/no-valid-active-team distinctly from a genuinely new database.
- [ ] Add state tests and an end-to-end smoke check for first launch, creation, quit, and restart.

## Acceptance checks

- [ ] A fresh database displays the welcome and contains zero team/domain rows until the user saves a team.
- [ ] Quit from welcome creates no team or other records.
- [ ] Create team leads to that team's normal overview/detail state and optional next-step prompts.
- [ ] Restart restores the selected team rather than repeating first-run setup.
- [ ] Archived/stale active selection is explained separately from empty first run.
- [ ] No example team, event, roster, result, or balance is seeded.

## Dependencies / boundaries

- Depends on [2.9](2.9-active-team-setting.md), [2.10](2.10-team-switcher-screen.md), and [2.11](2.11-create-team-form.md).
- Does not create a default season, driver, account balance, or event.
