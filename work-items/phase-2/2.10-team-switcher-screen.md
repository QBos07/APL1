# 2.10 — Build the team list and switcher screen

**Status:** Not started  
**Goal:** Let the user inspect and switch between team workspaces quickly without changing data merely by browsing.

## Work list

- [ ] Use the reusable list interaction from [2.3](2.3-list-table-interaction.md) to show active teams and an active marker.
- [ ] Show name and only known facts (for example, created date/latest activity when available); do not display invented season/balance summaries.
- [ ] Add actions for create, select/switch, view details, and optionally include archived teams.
- [ ] Require explicit activation to switch; highlighting or mouse-hovering a row must not change the active team.
- [ ] On switch, persist the stable team ID and return to the previous section in the newly active team.
- [ ] If no teams exist, offer the create-team flow; if the selected team became archived, show the fallback notice.
- [ ] Add a manual/smoke workflow and any terminal-free state tests.

## Acceptance checks

- [ ] The current team is clearly marked and displayed in the shared frame.
- [ ] Browsing/highlighting another team performs no write and does not switch context.
- [ ] Explicit selection persists across restart and screens then show the selected team's context.
- [ ] Archived teams are not switchable through the default active list but can be inspected when included.
- [ ] Empty-team and fallback-notice states are understandable.
- [ ] The screen calls shared use cases and contains no direct SQL.

## Dependencies / boundaries

- Depends on [2.2](2.2-shared-screen-frame.md), [2.3](2.3-list-table-interaction.md), [2.8](2.8-team-rename-archive.md), and [2.9](2.9-active-team-setting.md).
- Team creation form is a separate item ([2.11](2.11-create-team-form.md)).
