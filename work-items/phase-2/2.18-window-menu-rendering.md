# 2.18 — Render and operate the window-bar dropdowns

**Status:** Not started  
**Goal:** Make top-bar menus visible and operable by keyboard and mouse.

## Work list

- [ ] Draw the Overview, Settings, Help, and About headings in the top window bar.
- [ ] Render the currently open dropdown as an overlay aligned to its heading.
- [ ] Support keyboard focus/open/move/activate/close and mouse click-open/select using the menu model from 2.17.
- [ ] Route Overview items to existing overview views or honest placeholders; route Help to command/interaction help; route About to version/build information.
- [ ] Keep menu activation separate from data mutation; actions that change settings use a dialog/use case.
- [ ] Rebuild dropdown geometry/hit regions after resize and keep the selected body view underneath.
- [ ] Add automated state/hit-region tests and update the terminal smoke test for open/close/navigation.

## Acceptance checks

- [ ] All four top-level menus are visible in the window bar at supported sizes.
- [ ] Dropdowns open, navigate, and dismiss through both supported input paths.
- [ ] Clicking/activating a menu item selects the same action as keyboard activation.
- [ ] Version/About information is accurate and does not depend on the current working directory.
- [ ] Resizing while a menu is open leaves a valid, correctly positioned menu or closes it safely.
- [ ] No arbitrary data is generated by overview menu placeholders.

## Dependencies / boundaries

- Depends on [2.16](2.16-redesign-layout-geometry.md), [2.17](2.17-window-menu-model.md), and the mouse/focus decision in [2.0.2](2.0.2-mouse-focus-decision.md).
