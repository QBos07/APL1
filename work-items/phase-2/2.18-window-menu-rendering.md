# 2.18 — Render and operate the window-bar dropdowns

**Status:** Complete (2026-11-24)  
**Goal:** Make top-bar menus visible and operable by keyboard and mouse.

## Work list

- [x] Draw the Overview, Settings, Help, and About headings in the top window bar.
- [x] Render the currently open dropdown as an overlay aligned to its heading.
- [x] Support keyboard focus/open/move/activate/close and mouse click-open/select using the menu model from 2.17.
- [x] Route Overview items to existing overview views or honest placeholders; route Help to command/interaction help; route About to version/build information.
- [x] Keep menu activation separate from data mutation; actions that change settings use a dialog/use case.
- [x] Rebuild dropdown geometry/hit regions after resize and keep the selected body view underneath.
- [x] Add automated state/hit-region tests and update the terminal smoke test for open/close/navigation.

## Acceptance checks

- [x] All four top-level menus are visible in the window bar at supported sizes.
- [x] Dropdowns open, navigate, and dismiss through both supported input paths.
- [x] Clicking/activating a menu item selects the same action as keyboard activation.
- [x] Version/About information is accurate and does not depend on the current working directory.
- [x] Resizing while a menu is open leaves a valid, correctly positioned menu or closes it safely.
- [x] No arbitrary data is generated by overview menu placeholders.
