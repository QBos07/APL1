# 2.7 — Add team creation validation

**Status:** Not started  
**Goal:** Enforce team-name rules in a business operation that can be called from both menus and commands.

## Work list

- [ ] Add a team create use case/service that accepts user-entered values and calls the repository.
- [ ] Reject null/empty names and names that become empty after trimming whitespace.
- [ ] Normalize stored names consistently and enforce the uniqueness policy confirmed in [2.5](2.5-team-schema.md).
- [ ] Return a field-specific validation error without depending on Notcurses.
- [ ] Keep database constraints as a final integrity guard and translate duplicate constraint failures into a useful domain error.
- [ ] Add pure business-logic tests for required/name normalization and repository-backed tests for duplicate races/constraint behavior where practical.

## Acceptance checks

- [ ] Blank and whitespace-only names cannot create a row.
- [ ] A valid name is stored in the documented normalized form.
- [ ] Duplicate detection follows the confirmed case-sensitivity/archive policy.
- [ ] Validation failure inserts no row and does not change active-team state.
- [ ] The operation is callable without Notcurses and reports structured validation feedback.

## Dependencies / boundaries

- Depends on [2.5](2.5-team-schema.md), [2.6](2.6-team-repository-read-create.md), and [1.1](../phase-1/1.1-application-error-type.md).
- No screen/form is implemented here; menu and command entry arrive through later UI work.
