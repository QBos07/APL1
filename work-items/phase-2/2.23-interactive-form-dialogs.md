# 2.23 — Extend dialogs to support interactive forms

**Status:** Not started  
**Goal:** Evolve the existing confirmation/error overlay into a reusable dialog controller for short forms and choices.

## Work list

- [ ] Add dialog kinds for form, choice/list, information/error, and confirmation while keeping their state models terminal-free.
- [ ] Add focusable controls for text input, choice selection, Save/Cancel, and validation messages.
- [ ] Keep form input in dialog state and preserve it after validation failure.
- [ ] Trap focus inside an open dialog and restore the prior body/tab/menu focus when it closes.
- [ ] Support keyboard and mouse interaction using the established focus/hit-region routing.
- [ ] Keep dialogs modal: background tab/menu/body cannot be activated while a dialog is open.
- [ ] Add tests for control focus, typed values, validation retry, submit/cancel, focus restoration, and resize.

## Acceptance checks

- [ ] Form/choice dialog state can be tested without Notcurses or SQLite.
- [ ] Save returns entered values only after explicit submit; Cancel/Escape returns no committed values.
- [ ] Validation failure keeps all unrelated entered fields and identifies the invalid field.
- [ ] Keyboard focus is trapped while modal and restored when it closes.
- [ ] Mouse controls activate the same state transitions as keyboard controls.
- [ ] Dialog content reflows/resizes and remains usable at the documented minimum size.

## Dependencies / boundaries

- Builds on the completed confirmation/error dialog component ([2.4](2.4-confirmation-error-dialogs.md)) and new layout ([2.16](2.16-redesign-layout-geometry.md)).
- This component collects values; business validation/persistence remains in app/domain use cases.
