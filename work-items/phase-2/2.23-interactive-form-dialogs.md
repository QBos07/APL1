# 2.23 — Extend dialogs to support interactive forms

**Status:** Complete (2026-11-24)  
**Goal:** Evolve the existing confirmation/error overlay into a reusable dialog controller for short forms and choices.

## Work list

- [x] Add dialog kinds for form, choice/list, information/error, and confirmation while keeping their state models terminal-free.
- [x] Add focusable controls for text input, choice selection, Save/Cancel, and validation messages.
- [x] Keep form input in dialog state and preserve it after validation failure.
- [x] Trap focus inside an open dialog and restore the prior body/tab/menu focus when it closes.
- [x] Support keyboard and mouse interaction using the established focus/hit-region routing.
- [x] Keep dialogs modal: background tab/menu/body cannot be activated while a dialog is open.
- [x] Add tests for control focus, typed values, validation retry, submit/cancel, focus restoration, and resize.

## Acceptance checks

- [x] Form/choice dialog state can be tested without Notcurses or SQLite.
- [x] Save returns entered values only after explicit submit; Cancel/Escape returns no committed values.
- [x] Validation failure keeps all unrelated entered fields and identifies the invalid field.
- [x] Keyboard focus is trapped while modal and restored when it closes.
- [x] Mouse controls activate the same state transitions as keyboard controls.
- [x] Dialog content reflows/resizes and remains usable at the documented minimum size.

## Dependencies / boundaries

- Builds on the completed confirmation/error dialog component ([2.4](2.4-confirmation-error-dialogs.md)) and new layout ([2.16](2.16-redesign-layout-geometry.md)).
- This component collects values; business validation/persistence remains in app/domain use cases.


## Verification (2026-11-24)

- `src/tui/dialog.{h,c}` now supports confirmation, information/error, form, and
  choice kinds with fields, Save/Cancel controls, validation messages, disabled
  options, scrolling, and overlay-local hit testing.
- The shell draws all dialog kinds from the shared theme and routes keyboard and
  mouse controls through the same state transitions; form submit only returns
  values after explicit activation, and Cancel/Escape discards them.
- Modal focus uses `apl_tui_focus_push/pop`, so background regions cannot be
  activated while a dialog is open and the previous focus is restored on close.
- `tests/tui/test_tui_dialog.c` covers values, required-field retry, business
  errors, disabled choices, scrolling, hit regions, submit, and cancel.
- `ctest --test-dir cmake-build-debug --output-on-failure`: 2/2 tests pass.
