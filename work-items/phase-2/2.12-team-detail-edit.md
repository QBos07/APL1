# 2.12 — Build the team detail and edit screen

**Status:** Not started  
**Goal:** Provide a readable team profile view and safe editing for the fields supported in the team schema.

## Work list

- [ ] Show team name, optional notes, archive/current status, and record metadata that is useful to the user.
- [ ] Clearly distinguish entered profile fields from system-maintained metadata.
- [ ] Add an edit flow for name and notes that reuses validation from 2.7 and update behavior from 2.8.
- [ ] Add navigation links/placeholders for later team sections without implying those sections contain data.
- [ ] Provide archive action only when valid and require confirmation using [2.4](2.4-confirmation-error-dialogs.md).
- [ ] Preserve the caller's list/filter context when returning to the team list.

## Acceptance checks

- [ ] Detail view shows the exact saved profile data and labels missing optional values honestly.
- [ ] Editing persists through the shared use case and preserves the team ID.
- [ ] Duplicate/invalid name errors retain edits and identify the relevant field.
- [ ] Cancel leaves the saved team unchanged.
- [ ] Archive action is confirmed and cannot archive the last active team.
- [ ] Placeholder links do not create records or misleading summaries.

## Dependencies / boundaries

- Depends on [2.2](2.2-shared-screen-frame.md), [2.4](2.4-confirmation-error-dialogs.md), [2.8](2.8-team-rename-archive.md), and [2.10](2.10-team-switcher-screen.md).
- No financial, season, driver, or other domain panels are implemented here.
