# 2.5 — Add the team table migration

**Status:** Done (2026-11-24)
**Goal:** Add the first user-domain table without preloading any team or sample data.

## Confirmed v1 fields

- Stable database ID.
- User-entered team name, trimmed and non-empty.
- Optional profile notes.
- Creation/update timestamps maintained as record metadata.
- Archive timestamp/state; archived rows remain available to history.

Confirmed uniqueness rule: trimmed names are case-insensitively unique across
all teams, including archived teams, to avoid ambiguous switching and name
reuse. Blank/whitespace-only names are rejected.

## Implementation notes (2026-11-24)

- Confirmed uniqueness policy: names are trimmed, must be non-empty, and are
  case-insensitively unique across **all** teams, including archived teams.
  This prevents ambiguous switching and accidental reuse of historical names.
- Migration 2 creates `teams` with stable integer ID, case-insensitive unique
  name, optional notes, archive flag/timestamp, and created/updated timestamps.
  It creates no team or other domain rows. The active-team setting is migration
  3 (2.9), keeping this slice to team data only.
- Tests: `test_db_initial_migration.c` (empty teams, latest version),
  `test_team_repository.c` (constraints/duplicates), and the upgrade path tested
  by the real v1→v3 migration in `test_app_lifecycle.c`.
