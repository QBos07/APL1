# 2.3 — Add one reusable list/table interaction

**Status:** Not started  
**Goal:** Provide a small reusable widget/state model for browsing selectable rows before building the team switcher.

## Work list

- [ ] Define the minimum row/view interface needed to display a label and optional secondary summary; avoid a generic database grid framework.
- [ ] Implement focus/selection, up/down movement, activation, and scrolling for visible rows.
- [ ] Add mouse row focus/selection and wheel scrolling according to [2.0.2](2.0.2-mouse-focus-decision.md).
- [ ] Show a visible selection/focus indicator independent of color.
- [ ] Draw explicit empty and no-results states.
- [ ] Keep list state (selected row, first visible row, dimensions) testable without Notcurses.
- [ ] Recalculate visible rows after resize while retaining a valid selected record when possible.

## Acceptance checks

- [ ] Keyboard navigation, mouse selection, activation, and scrolling follow the documented model.
- [ ] Selection remains within valid row bounds when data is empty, rows are added/removed, or the terminal resizes.
- [ ] Empty/no-match states are visible and do not look like rendering failures.
- [ ] The widget receives row data from its caller and performs no SQL or domain mutations.
- [ ] Unit tests cover selection bounds, scrolling, activation, empty data, and resize calculations.

## Dependencies / boundaries

- Depends on [2.0.1](2.0.1-tui-layout-resize-decision.md), [2.0.2](2.0.2-mouse-focus-decision.md), and [2.2](2.2-shared-screen-frame.md).
- Implement only the interaction needed by the team list initially; add filtering/sorting later with the feature that needs it.
