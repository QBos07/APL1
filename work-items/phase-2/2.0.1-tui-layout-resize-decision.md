# 2.0.1 — Decide the TUI plane and resize model

**Status:** Done (2026-11-24)
**Goal:** Make the layout/redraw strategy explicit before replacing the Phase 1 shell with multi-region screens.

## Decision

The shared frame uses dedicated Notcurses planes for independently drawn regions:
a header (section title and active team), a body (lists, tables, forms, or detail
views), an actions line, a status/message line, and a modal overlay. The standard
plane is the base surface only; drawing text on it is the sole exception, used for
the "terminal too small" notice.

The geometry is computed by a pure function in `src/tui/layout.h`/`layout.c`. The
frame module planned for 2.2 applies those rectangles to Notcurses planes. No screen
module calculates terminal geometry itself.

### Plane ownership

| Plane | Owner | Created | Resized / moved | Destroyed | Contents |
| --- | --- | --- | --- | --- | --- |
| Standard plane | Notcurses context (`apl_tui`) | `notcurses_init` | Notcurses on terminal resize | `notcurses_stop` | Base background; the too-small notice only |
| Header | Frame | First normal draw, or when returning from too-small mode | Frame on resize | Frame on teardown or too-small transition | Section title, active-team context |
| Body | Frame | Same as header | Frame on resize | Frame on teardown or too-small transition | Current list/detail/form region |
| Actions | Frame | Same as header | Frame on resize | Frame on teardown or too-small transition | Available action hints/controls |
| Status | Frame | Same as header | Frame on resize | Frame on teardown or too-small transition | Validation, save confirmation, errors |
| Modal overlay | Frame | When a modal opens | Frame on resize while open | Frame when the modal closes, on teardown, or on too-small transition | Confirmation/dialog content |

Rules:

- `apl_tui` continues to own exactly one `struct notcurses` context. The frame
  borrows that pointer for its lifetime and never calls `notcurses_stop`.
- The frame owns every child plane. Screen modules borrow a region plane only for
  the duration of one draw; they must not create, resize, move, erase, or destroy
  frame planes, and must not retain plane pointers across draws.
- The modal controller owns the modal's state and content. The frame owns the
  overlay plane and its geometry. Opening/closing a modal goes through the frame,
  not through ad-hoc plane creation in a screen.
- All persistent planes are children of the standard plane, placed at absolute
  terminal coordinates. They are siblings, not children of one another, and do
  not use `NCPLANE_OPTION_MARGINALIZED` or automatic resize callbacks: resize
  policy stays in one place instead of being spread through Notcurses callbacks.
- The overlay is moved to the top of the pile while open. Background regions keep
  their semantic state but receive no input while the modal is active.
- On teardown the frame destroys child planes in any order (they do not overlap)
  and never destroys the standard plane. Destruction is safe on a partially
  created frame.

### Layout calculation

`apl_tui_layout_compute(rows, cols)` is a pure function: no Notcurses context,
allocation, environment access, or mutable global state. It returns absolute
rectangles in terminal cells.

Supported minimum: **40 columns x 10 rows** (functional minimum). **80x24** is the
recommended and default smoke-test size. Notcurses 3.0 can initialize with a much
smaller standard plane, but the application frame needs three chrome rows plus at
least one usable body row, and 40 columns is the smallest width in which the
header/actions/status lines remain meaningful. Below the minimum the application
does not create child planes at all.

Normal mode (`rows >= 10`, `cols >= 40`) tiles the terminal without overlap:

| Region | y | x | rows | cols |
| --- | --- | --- | --- | --- |
| header | 0 | 0 | 1 | `cols` |
| body | 1 | 0 | `rows - 3` | `cols` |
| actions | `rows - 2` | 0 | 1 | `cols` |
| status | `rows - 1` | 0 | 1 | `cols` |

The modal overlay is centered inside the body so the frame context and status
remain visible:

```text
overlay_rows = min(body.rows, max(7, body.rows * 3 / 4))
overlay_cols = min(body.cols, max(24, body.cols * 3 / 4))
overlay_y    = body.y + (body.rows - overlay_rows) / 2
overlay_x    = (body.cols - overlay_cols) / 2
```

All arithmetic is unsigned integer arithmetic; `body` is at least 7 rows, so the
floors fit. At the minimum 40x10 terminal the overlay fills the body (7 rows) so
the dialog title, wrapped message, and action buttons remain usable; the frame
header, actions, and status stay visible outside the body. There are no shared gutters or border columns in v1. A screen may draw
a border or separator inside its own rectangle, but must not draw outside it.

Too-small mode (any dimension below the minimum, including zero) sets
`APL_TUI_LAYOUT_TOO_SMALL` and zeroes every rectangle. The frame shows one notice
on the standard plane, for example:

```text
Terminal too small: need at least 40x10, have 32x9. Resize or press q to quit.
```

The notice is clipped by the standard plane; only row 0 is used, and drawing is
skipped if the plane has no rows. This is the only standard-plane text.

### Resize and redraw protocol

1. `notcurses_get_*` returns `NCKEY_RESIZE` (or a screen/controller requests a
   redraw after changing content).
2. Read the current dimensions from the standard plane with
   `notcurses_stddim_yx` / `ncplane_dim_yx`.
3. Recompute the layout with `apl_tui_layout_compute`.
4. Normal -> too-small: destroy the overlay and all frame planes, erase the
   standard plane, draw the notice on row 0, and render. The semantic screen,
   including an open modal's state, is retained so resizing back restores it.
5. Too-small -> normal, or normal -> normal: ensure all frame planes exist.
   Resize each with `ncplane_resize_simple`, then place it with
   `ncplane_move_yx`. Resize the overlay too when a modal is open. Planes are
   erased because growing leaves undefined/stale content.
6. Create the overlay at the computed rect if a modal is open; destroy it if the
   modal has closed.
7. Invalidate all resize-dependent state: hit regions (2.0.2), viewport/selection
   visibility calculations, and any cached text sizes. Recompute them from current
   content before dispatching the next input event.
8. Redraw every visible region from the current application/screen state, then
   call `notcurses_render` once. The frame does not copy the previous render as its
   source of truth, so a complete redraw cannot resurrect stale content.
9. Geometry failure (`ncplane_resize_simple`, `ncplane_move_yx`,
   `ncplane_create`, or `notcurses_render` returning non-zero) returns
   `APL_ERR_TUI_RENDER`; the top-level cleanup destroys the frame and stops the
   TUI. The pure layout prevents invalid zero-sized plane arguments on normal
   paths, so such a failure indicates a terminal/library fault rather than a
   layout bug.

`stdplane_erase` is **not** the resize/re-layout strategy. The standard plane is
erased only when entering too-small mode, where no child planes may exist. Normal
frames redraw and erase their own planes.

Input handling keeps one blocking loop: after a resize is read, the next loop
iteration completes layout, hit-region rebuild, and full redraw before reading the
next event. Mouse events already queued are interpreted against the new layout
when they are read; stale hit regions are never used.

### What is unit-testable without a terminal

- Layout rectangle computation, mode selection, tiling/non-overlap, and overlay
  placement (`tests/tui/test_tui_layout.c`).
- Later viewport math for list scrolling and visible selection (2.3), because it
  is pure state-to-row-range arithmetic.
- Hit-testing and focus transitions (2.0.2/2.3), using synthetic rectangles and
  screen state.
- Text is clipped by Notcurses plane boundaries during drawing; modules do not
  pre-truncate UTF-8 by byte count, so a multibyte code point is never split by
  layout code.

Not unit-testable without a terminal: actual plane creation, z-order, terminal
SIGWINCH delivery, and rendered output. Those are covered by the opt-in TUI smoke
test, extended in 2.2 to resize across the 40x10 boundary and back, and to verify
there is no stale content after each resize.
