# 2.4 — Add reusable confirmation and error dialogs

**Status:** Done (2026-11-24)
**Goal:** Provide consistent, testable modal behavior for confirming risky actions and explaining failures.

## Implementation notes (2026-11-24)

- `src/tui/dialog.{h,c}` defines dialog kind/result state independently of
  drawing; confirmations start with Cancel focused, and activation returns
  ACCEPTED or DISMISSED to the caller.
- The shell renders the modal in the body-centred overlay, wraps the message,
  supports keyboard focus and mouse clicks on Cancel/Confirm, and treats Escape
  as dismissal without invoking the pending action.
- Archive confirmation and unsaved-form discard use the same component; error
  dialogs use the same bounded/wrapped layout. Tests: `test_tui_dialog.c`
  plus the archive smoke workflow.

## Work list

## Acceptance checks

- [x] The caller receives an explicit dialog result and remains responsible for executing the confirmed operation.
- [x] Cancel/dismiss cannot accidentally perform a destructive action.
- [x] Keyboard and mouse users can reach the same choices, with visible focus.
- [x] Error text is readable at supported sizes and does not silently disappear.
- [x] Dialog state/result tests do not require Notcurses or SQLite.
