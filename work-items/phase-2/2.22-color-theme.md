# 2.22 — Add a consistent color theme

**Status:** Complete (2026-11-24)  
**Goal:** Make the interface feel like a polished modern TUI while retaining readable operation on limited-color terminals.

## Work list

- [x] Define semantic style roles for window bar, dropdown, active tab, inactive tab, active team, body, selection/focus, dialog, success, warning, and error.
- [x] Implement styles centrally so screens do not invent incompatible color pairs.
- [x] Check terminal color capability and fall back to text markers/bold/reverse styles when colors are unavailable.
- [x] Use readable contrast and avoid using hue as the sole signal for status or focus.
- [x] Keep colors stable across resize/redraw and when dialogs/menus are open.
- [x] Add a style-role test and manual checks in full-color and restricted/no-color terminals.
- [x] Expose theme selection only if a real alternate theme is implemented; otherwise keep Settings entry as a clear future placeholder.

## Acceptance checks

- [x] The top bar, tab rail, body, status bar, menus, and dialogs share one coherent palette.
- [x] Active tab/team, keyboard focus, selected row, success, warning, and error are visually distinct.
- [x] Text/markers preserve the distinction in monochrome or limited-color modes.
- [x] No individual screen hard-codes an unrelated palette.
- [x] Color initialization failure does not prevent keyboard/mouse use.

## Dependencies / boundaries

- Depends on [2.16](2.16-redesign-layout-geometry.md); can be developed alongside 2.18–2.21.
- User-configurable theme editing is out of scope unless implementation experience makes it a small, clear addition.


## Verification (2026-11-24)

- `src/tui/theme.{h,c}` defines semantic roles for the window bar, dropdowns,
  tabs, team, body, selection, dialogs, success/warning/error, and muted text.
  Roles are applied centrally with one palette and a reverse/attribute fallback
  when `notcurses_canchangecolor` is false.
- The shell now uses only theme roles for windows, menus, tabs, list selection,
  dialogs, status, and the legacy team form; textual markers remain the primary
  focus/status signal.
- `tests/tui/test_tui_theme.c` checks distinct color/style roles and the
  monochrome fallback. Smoke rendering still passes with `xterm-256color`.
- `ctest --test-dir cmake-build-debug --output-on-failure`: 2/2 tests pass.
