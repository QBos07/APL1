# 6.11 — Add part register views and forms

**Status:** Planned  
**Goal:** Let users maintain types and individual units through the Parts window.

## Work list

- [ ] Add part-type and individual-unit list/detail routes in Parts, scoped to the active team.
- [ ] Add create/edit dialogs for types and units, with optional serial/part number clearly marked and visible archived state.
- [ ] Add archive confirmation for types/units and retain access to archived records from historical details.
- [ ] Offer an explicit create-or-select flow when a lifecycle/replacement form needs a unit; never create a duplicate unit silently.
- [ ] Preserve list filters/selection when opening details or returning from dialogs; expose keyboard and mouse actions.
- [ ] Add screen/controller tests and smoke coverage for create, edit, archive, optional identifiers, cancel, validation recovery, and team switching.

## Acceptance checks

- [ ] Every register create/edit/archive action uses the type/unit use cases from 6.1 and 6.2.
- [ ] Archived types are not offered for new units by default; existing linked units/history remain visible.
- [ ] Cancelling creates/edits/archives no change; validation errors retain entered values.
- [ ] Empty register states ask the user to create their own type/unit and do not seed sample records.
- [ ] User can distinguish type identity from an individual unit and can omit a serial number.

## Dependencies / boundaries

- Depends on [6.1](6.1-part-type-schema-repository.md), [6.2](6.2-part-unit-schema-repository.md), Phase 2 dialogs/lists, and ARCH-07.
- Current-fitment and unit lifecycle detail is covered in 6.8.
- Does not add inventory or compatibility screens.
