# 6.12 — Add install, remove, repair, and dispose forms

**Status:** Implemented  
**Goal:** Make every non-replacement lifecycle operation available as a guided, reviewable action.

## Work list

- [x] Add install and remove forms with explicit unit, car/position, entered date, and optional event/reason/usage/notes.
- [x] Add repair and dispose forms with the relevant unit, entered date, and optional car/position/event/reason/usage/notes.
- [x] Before save, summarize the affected unit and expected fitment effect; repair must show that fitment does not change.
- [x] Reuse lifecycle use cases from 6.5; preserve typed values and focus the invalid field after validation errors.
- [x] Confirm destructive/irreversible disposal; Cancel or rejected transitions must create no lifecycle or audit event.
- [x] On success, refresh current fitment and history, show confirmation, and open/select the new event or affected unit.
- [x] Add keyboard/mouse/controller and smoke tests for all actions, invalid transitions, cancel, confirmation, and persistence after reopen.

## Acceptance checks

- [x] Install/remove/repair/dispose are all available from the Parts window and call the shared 6.5 use cases.
- [x] No form invents a date, event, reason, usage, serial number, or stock state.
- [x] Invalid transitions preserve entered values and do not partially update current fitment/history.
- [x] Repair never changes fitment; disposal cannot leave a unit recorded as currently fitted.
- [x] Successful writes remain inspectable in the unit and lifecycle history views.

## Dependencies / boundaries

- Depends on [6.5](6.5-lifecycle-use-cases.md), [6.8](6.8-fitment-and-unit-views.md), [6.11](6.11-part-register-views-forms.md), Phase 2 dialog patterns, and ARCH-07.
- Atomic replacement has its own preview/save form in 6.9.
- Command routes are handled in Phase 8; these forms are the handoff target for incomplete commands.
