# 6.4 — Add lifecycle repository queries

**Status:** Implemented  
**Goal:** Read component histories and calculate recorded current fitment without overwriting events.

## Work list

- [x] Add append/get/list repository operations for lifecycle events with caller-owned transaction boundaries.
- [x] Add chronological history queries by unit, car/position, action, and date range with deterministic tie ordering.
- [x] Add a current-fitment query derived from install/remove/replace event sequences; do not treat absence of history as proof that no unit is fitted.
- [x] Include a replace event in both the old and new unit histories while returning it only once in operation-level lists.
- [x] Respect active-team scope and allow explicit inclusion of archived types/units/cars for historical reads.
- [x] Add integration tests for current state after each action, chronological history, filters, empty/unknown state, archived references, and team isolation.

## Acceptance checks

- [x] Current-fitment results are deterministic and derived only from recorded lifecycle entries.
- [x] No history returns an unknown/unrecorded state, distinct from an explicit remove/no-unit state.
- [x] Replacement preserves inspectable history for both units without duplicating the operation itself.
- [x] Repository queries use bound parameters, indexed access paths where applicable, and safe list allocation.

## Dependencies / boundaries

- Depends on [6.3](6.3-lifecycle-schema.md), [6.1](6.1-part-type-schema-repository.md), [6.2](6.2-part-unit-schema-repository.md), and ARCH-02.
- Current-fitment and detail presentation are in 6.8; filters in 6.10.
- The repository does not infer on-hand inventory or validate all lifecycle transitions; use cases own transition rules.
