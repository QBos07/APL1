# 6.8 — Add current-fitment table and part-unit detail

**Status:** Planned  
**Goal:** Let users inspect recorded fitment and each unit's complete lifecycle history.

## Work list

- [ ] Add a Parts body view showing current recorded fitment by car/position, unit/type identity, and known entered details.
- [ ] Distinguish “unknown/not recorded” (no establishing lifecycle event) from “no unit fitted” (explicit remove/dispose state).
- [ ] Add part-unit detail with type, serial/part number when entered, notes/status, fitment state, chronological events, and linked ledger transaction/cost history.
- [ ] Show replace events in both old/new unit histories and make their paired transition clear.
- [ ] Mark calculated current fitment and net linked cost as derived; show the active team and relevant car/position scope.
- [ ] Preserve list selection/filter state when opening details and add keyboard/mouse controller tests plus smoke coverage.

## Acceptance checks

- [ ] No unrecorded fitment is presented as an empty position or “available” part.
- [ ] Historical removal/replacement records remain inspectable after the unit/type/car is archived.
- [ ] Linked costs open the original ledger transaction and show correction-aware values without duplicate cost rows.
- [ ] Empty, unknown, no-fitment, populated, and archived-history states are visually distinct.
- [ ] Screen behavior follows shared layout, resize, focus, and dialog patterns without expanding `shell.c` feature logic.

## Dependencies / boundaries

- Depends on [6.4](6.4-lifecycle-repository.md), [6.7](6.7-replacement-cost-link.md), Phase 2 list/detail patterns, and ARCH-07.
- Part type/unit management screens are specified in 6.11; lifecycle entry forms are in 6.9 and 6.12.
- No inferred stock, reliability, lifespan, or recommendation display.
