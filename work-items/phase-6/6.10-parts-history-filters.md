# 6.10 — Add parts-history filters

**Status:** Implemented  
**Goal:** Make part and lifecycle history findable using the fields users actually record.

## Work list

- [x] Add section-level text search for part type/name, serial number, part number, and notes where appropriate.
- [x] Add filters for car, position, date range, lifecycle action, and type; allow explicit inclusion of archived records.
- [x] Show active filter chips/labels, result count, clear-filter action, and clear no-match state.
- [x] Preserve filters and selected row when opening unit, type, lifecycle, or linked transaction details.
- [x] Add repository/query and headless TUI tests for filter composition, team scope, ordering, archived history, and empty/no-match behavior.

## Acceptance checks

- [x] Filters match only entered values and do not infer serials, fitment, or availability.
- [x] Default views remain scoped to the active team and exclude archived records unless explicitly requested.
- [x] Filter context and result count are visible and restored after returning from detail.
- [x] Search/filter behavior uses explicit query pieces and indexes, not a universal query language.

## Dependencies / boundaries

- Depends on [6.4](6.4-lifecycle-repository.md), [6.8](6.8-fitment-and-unit-views.md), and ARCH-08 query-filter foundations.
- Command equivalents for every Parts filter/action are added in Phase 8.
- Saved views and cross-team reports remain deferred.
