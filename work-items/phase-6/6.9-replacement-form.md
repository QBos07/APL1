# 6.9 — Add replacement workflow form

**Status:** Planned  
**Goal:** Provide a guided, reviewable replacement flow that commits the old/new transition atomically.

## Work list

- [ ] Add a replacement form to select car/position, currently fitted old unit, and new unit; allow creating a new unit through an inline form calling the shared part-unit use case.
- [ ] Collect required entered date and optional event/reason/usage/notes; do not invent defaults for business values.
- [ ] Allow selecting an existing eligible expense transaction or leaving cost unlinked; never create a duplicate cost entry from the replacement form.
- [ ] Review team/car/position, old/new unit, date, optional details, and linked transaction/currency before save.
- [ ] On save, call the replacement use case and cost-link operation within their documented atomic boundaries; show a clear result and refreshed fitment.
- [ ] Preserve entered form values after validation errors; Cancel must leave fitment, lifecycle history, and ledger unchanged.
- [ ] Add TUI/controller and smoke tests for valid save, cancel, ambiguity, invalid references, transaction selection, and reopen persistence.

## Acceptance checks

- [ ] The proposed old/new fitment and financial link are visible before commit.
- [ ] The review/save path cannot silently install a unit that is already fitted or disposed.
- [ ] A failed or cancelled form leaves the old unit current and creates no partial replacement/cost link.
- [ ] Successful save updates the derived fitment and links at most one existing ledger expense.
- [ ] Keyboard and mouse paths use the same use cases and have explicit Save/Cancel actions.

## Dependencies / boundaries

- Depends on [6.2](6.2-part-unit-schema-repository.md), [6.6](6.6-replacement-use-case.md), [6.7](6.7-replacement-cost-link.md), [6.8](6.8-fitment-and-unit-views.md), and ARCH-07.
- Repair/install/remove/dispose forms are in 6.12; inline creation uses the shared unit use case from 6.2.
- No command routes are added here; full parity is Phase 8.
