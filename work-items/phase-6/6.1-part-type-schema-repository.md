# 6.1 — Add part-type schema, repository, and core use cases

**Status:** Implemented  
**Goal:** Persist user-defined component categories/types without imposing a catalogue or stock system.

## Data policy

- A part type belongs to one team and has a stable ID, required user-entered category and name, optional description/notes, and shared record metadata.
- Category and name are user-maintained labels. Do not seed common F1 part types or assume compatibility.
- Archiving a type excludes it from default new-unit pickers but does not erase or invalidate existing units/history.
