# 4.12 — Add budget-plan validation and save use case

**Status:** Done  
**Goal:** Validate and audit user-authored budget plans without treating them as spending or authorization.

## Work list

- [x] Add a plan create/update application operation with structured validation for team, period, category, planned amount, currency, and optional season reference.
- [x] Enforce nonblank category, valid date/period boundaries, nonnegative planned limit (unless the decision explicitly permits another meaning), and team reporting currency.
- [x] Apply the 4.11 uniqueness policy consistently: update an existing plan or return a clear conflict rather than creating ambiguous duplicates.
- [x] Save plan changes and activity events atomically using shared transaction helpers; record changed fields and before/after values without copying unrelated data.
- [x] Permit editing a plan while preserving auditable changes; do not create a ledger transaction or alter actual balance.
- [x] Add unit/integration tests for boundaries, duplicate behavior, invalid references, audit changes, no-op updates, rollback, and team isolation.

## Acceptance checks

- [x] Invalid plans write neither plan data nor activity history.
- [x] Valid plan changes are attributable in History with understandable old/new values.
- [x] Editing a plan has no effect on the ledger or calculated balance.
- [x] Plan period/category scope is explicit and consistent with 4.13 calculations.
- [x] Overspending is never rejected by the plan use case or by the income/expense use cases.

## Dependencies / boundaries

- Depends on 4.1 and 4.11, ARCH-01, ARCH-05, and the Phase 3 activity repository.
- This use case does not add plan forms or report presentation.
- No forecasts, committed-cost records, or automatic plan generation are included.
