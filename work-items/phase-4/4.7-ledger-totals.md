# 4.7 — Add derived balance and ledger totals

**Status:** Done  
**Goal:** Calculate financial summaries from posted entries only, with explicit scope and exact arithmetic.

## Work list

- [x] Add service/query operations for current balance and totals by entered date range and normalized category.
- [x] Derive current balance by summing signed balance deltas; exclude opening balances from period income/expense totals.
- [x] Derive income and expense actuals by their original transaction classification, applying linked reversals/adjustments so corrected entries reduce or replace the original contribution rather than double-counting it.
- [x] Keep all arithmetic in checked integer minor units; return an overflow error rather than wrapping or using floating point.
- [x] Support empty ledgers, inclusive/exclusive date bounds as defined in 4.1, and category/type filters.
- [x] Show corrected net values in summary totals while retaining gross posted entries in the transaction list/detail and correction history.
- [x] Add unit and SQLite integration tests for empty state, sign convention, filters, boundaries, currency, overflow, and correction cases.

## Acceptance checks

- [x] Current balance is computed from ledger entries and is never read from an independently editable balance column.
- [x] Reports identify their date/category scope and currency.
- [x] Empty results are represented as no recorded entries / zero derived total without implying missing data is a user-entered zero.
- [x] Results remain exact at integer boundaries and fail safely on overflow.
- [x] Budget plans are never included in actual totals.

## Dependencies / boundaries

- Depends on 4.3–4.6 and ARCH-06's money primitives.
- This item supplies query/calculation data; screen presentation is in 4.8 and budget-versus-actual is in 4.13.
- No forecasting, exchange conversion, or cross-team aggregation is added.
