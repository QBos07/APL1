# 4.10 — Add traceable transaction corrections

**Status:** Done  
**Goal:** Correct a posted amount without erasing the original entry or obscuring its effect on the ledger.

## Work list

- [x] Implement correction within the ARCH-06 append-oriented model: create a reversal of the original entry, optionally followed by a replacement adjustment/entry. A reversal has the opposite balance effect and retains the original income/expense classification for net report calculations.
- [x] Store stable links between correction entries and the original; prevent cross-team references, duplicate reversal, and invalid correction chains.
- [x] Make a correction an atomic use case: all required reversal/replacement entries and audit events commit together or none do.
- [x] Keep the original entry readable and mark its corrected/reversed state as derived from linked entries, not by mutating its amount.
- [x] Add a correction review dialog showing original value, proposed reversing/replacement values, resulting balance impact, date, and reason/description before save.
- [x] Add tests for full reversal, replacement amount, repeated/invalid correction, overflow, rollback, audit history, and historical/current totals.

## Acceptance checks

- [x] The original amount and details remain inspectable after correction.
- [x] A reversal neutralizes the original contribution according to the documented sign convention; a replacement is separately identifiable.
- [x] Failure at any write/audit step leaves the prior ledger and balance unchanged.
- [x] Correction history makes the old value, correction, and resulting net effect understandable.
- [x] Correction is not implemented as unlogged SQL update/delete or as a direct balance edit.

## Dependencies / boundaries

- Depends on 4.2–4.9, ARCH-01, ARCH-05, and ARCH-06.
- Use reversal/adjustment entries; do not add a general-purpose edit history for mutable posted transactions.
- Corrections do not delete audit activity and do not silently rewrite prior reports; reports must follow the net/gross policy fixed in 4.7.
