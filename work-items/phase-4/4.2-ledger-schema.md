# 4.2 — Add the ledger and category schema

**Status:** Done  
**Goal:** Persist team-scoped, user-entered ledger entries without storing a mutable balance.

## Work list

- [x] Add a migration for ledger entries with a stable ID, team ID, signed minor-unit amount, currency code, entered date, type, category label, description, and system creation timestamp.
- [x] Support explicit entry kinds for opening balance, income, expense, reversal, and adjustment; document the sign convention so one entry contributes predictably to the derived balance.
- [x] Store the team's reporting currency (or use an already-established team currency field if one exists) and enforce the selected v1 policy from [4.1](4.1-money-and-currency-policy.md).
- [x] Represent correction relationships with stable references to the original entry; preserve the original row and its entered values.
- [x] Add foreign keys, check constraints, and indexes for team/date ordering, team/type, and any correction lookup needed by the repository.
- [x] Keep budget plans out of the ledger schema; they are introduced in 4.11.
- [x] Add migration and rollback/failure tests; verify migrations create no ledger entries or default categories.

## Acceptance checks

- [x] A fresh migration creates schema only and invents no team, currency choice, category, or money record.
- [x] Invalid entry kinds, malformed required values, impossible references, and cross-team correction links are rejected by constraints where practical.
- [x] Amounts are stored as integers, and no balance column or update-in-place correction path exists.
- [x] Existing databases migrate and roll back consistently with the migration framework.
- [x] Integration tests confirm foreign keys, indexes/schema version, and the no-seeded-data rule.

## Dependencies / boundaries

- Depends on [4.1](4.1-money-and-currency-policy.md), ARCH-06, the Phase 1 migration runner, and the team repository/schema.
- Schema only: transaction operations are in 4.3; validation and business rules are in 4.4–4.6.
- Do not add project, event, or part links yet; those features can add stable optional links in their own phase without duplicating transaction records.
