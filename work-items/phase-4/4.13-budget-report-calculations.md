# 4.13 — Add budget-versus-actual calculations

**Status:** Done  
**Goal:** Compare a user's plan with matching recorded actuals and surface variance without conflating the two.

## Work list

- [x] Add report query/service operations joining budget plans with expense ledger totals by team, currency, period, and normalized category.
- [x] Define variance sign and labels (planned, actual, remaining/over plan) and document them for the screen.
- [x] Calculate using checked integer minor units and the correction-aware net actual semantics selected in 4.7.
- [x] Treat no plan and no actuals as distinct states; do not turn either missing side into an implied entered value.
- [x] Return a visible overspend warning when actual exceeds plan, but do not block expense entry or imply that the plan is an authorization limit.
- [x] Add tests for no plan/no actual, plan only, actual only, exact match, under/over plan, corrections, date/category filters, currency, and overflow.

## Acceptance checks

- [x] Report rows disclose team, currency, period, category, and included actual-entry semantics.
- [x] Budget plan values never enter ledger or actual calculations.
- [x] Corrected/reversed transactions are handled consistently with the correction policy.
- [x] Overspend appears as a warning and never prevents recording a real expense.
- [x] All values are exact and overflow is an explicit error.

## Dependencies / boundaries

- Depends on 4.7, 4.11, and 4.12.
- Calculations only; budget list/edit forms and report screen are in 4.14.
- No forecasting, annualization, inferred future spend, or cross-currency aggregation.
