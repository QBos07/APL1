# 4.9 — Add guided ledger entry forms

**Status:** Done  
**Goal:** Add clear income, expense, and opening-balance flows that call the same application operations as any future command route.

## Work list

- [x] Add guided forms for income, expense, and opening balance with required/optional fields documented beside the inputs.
- [x] Prefill active team and its reporting currency visibly; require explicit currency selection when team configuration is not yet present.
- [x] Collect exact amount, entered date, category label, and description; preserve typed values and identify the invalid field after validation failure.
- [x] Review a concise save summary showing team, currency, kind, amount, date, category, and description before commit.
- [x] On success, show confirmation, refresh derived totals, and select/open the newly created transaction in the list.
- [x] Ensure cancel closes without writes and that menus/actions call the application use cases rather than duplicating validation.
- [x] Add TUI/controller and smoke tests for save, cancel, validation recovery, review, and persistence after reopen.

## Acceptance checks

- [x] No form silently supplies an amount, date, category, description, or opening balance.
- [x] Currency and target team are visible at review time; mixed-currency entries cannot be saved.
- [x] Validation errors preserve values and direct focus to the relevant input.
- [x] Save and cancel are explicit, with no save-on-close behavior.
- [x] The saved row and displayed balance agree with repository/service results.

## Dependencies / boundaries

- Depends on 4.5–4.8, shared dialog/form support, and ARCH-07.
- This does not add ex-style money commands; they are part of Phase 8 after command vocabulary is established.
- Category labels are user-entered under 4.1; do not seed category choices or add an unrelated category-administration screen.
