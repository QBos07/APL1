# 4.11 — Add budget-plan schema and repository

**Status:** Done  
**Goal:** Persist user-entered budget plans separately from actual ledger entries.

## Work list

- [x] Add a migration for team-scoped budget plans with stable ID, period/date range, optional user-created season reference if applicable, category label, planned minor-unit amount, currency, notes if needed, and system timestamps.
- [x] Define the v1 plan scope and uniqueness/update policy (for example, one plan per team, period, and normalized category).
- [x] Keep plans as planned amounts only; never insert a plan into the transaction ledger or actual-spending totals.
- [x] Add create/get/list repository operations with team, period, category, and season filters; use parameterized SQL and caller-owned transactions.
- [x] Add foreign keys/check constraints and indexes for common team/period/category reads.
- [x] Add migration and integration tests for persistence, ordering, filters, uniqueness policy, team isolation, and rollback.

## Acceptance checks

- [x] Schema creates no default budgets, categories, or periods.
- [x] Plan amount uses exact minor units and the team's reporting currency.
- [x] Repository does not expose an operation that creates or changes a transaction as a side effect.
- [x] Plans are separately queryable and cannot be confused with actual ledger entries.
- [x] Cross-team references/writes are rejected or returned as not found.

## Dependencies / boundaries

- Depends on 4.1 and 4.2 for money/category/currency policy and the existing season repository if plans link to user-created seasons.
- This item stores plans only; validation/audit use case is 4.12 and actual comparison is 4.13.
- Keep periods user-defined via explicit date range and/or existing user-created season; do not generate a financial calendar or seeded budget.
