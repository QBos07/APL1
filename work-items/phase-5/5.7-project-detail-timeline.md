# 5.7 — Add project detail and timeline view

**Status:** Done  
**Goal:** Give users one inspectable view of entered project information, dated updates, and related actual costs.

## Work list

- [x] Add project detail showing all entered fields, current user-entered status, optional season/car references, notes, and archive state.
- [x] Add a chronological update timeline with each entered date, summary, status change (when present), notes, and distinct system-created timestamp only where useful.
- [x] Show linked ledger transactions and a derived net actual-cost total using the correction-aware query from 5.5.
- [x] Label costs as ledger-derived actuals; do not add an independent project actual-cost number or progress percentage.
- [x] Provide contextual edit/archive/add-update actions through the shared application use cases and retain the source list state on return.
- [x] Add tests for projects with no updates, no costs, archived references, mixed timeline dates, corrected transactions, and active-team isolation.

## Acceptance checks

- [x] Project details distinguish user-entered facts from ledger-derived totals and system metadata.
- [x] No updates/costs are represented as “not recorded” rather than fabricated completion/progress or an invented cost.
- [x] Timeline sorting is stable and based on entered date, not assumed creation order.
- [x] A transaction detail can be opened from a project without losing the project context on return.
- [x] Archived projects and their history remain inspectable without making them default choices for new links/updates.

## Dependencies / boundaries

- Depends on [5.2](5.2-project-use-cases.md), [5.4](5.4-project-update-use-case.md), [5.5](5.5-project-transaction-links.md), [5.6](5.6-project-list-filters.md), and ARCH-07.
- Does not add project-level forecasts, a second budget system, or independent actual-cost input.
- Contextual command routes are not implemented here; they are added in Phase 8.
