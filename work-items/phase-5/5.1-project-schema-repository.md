# 5.1 — Add development-project schema and repository

**Status:** Planned  
**Goal:** Persist user-created development projects with stable team and reference links.

## Data policy

- A project belongs to one team and has a stable ID, required user-entered title, optional user-entered category and description, optional target/actual dates, current user-entered status, notes, and shared record metadata.
- Category and status are labels, not a prescribed development workflow. Do not seed values, calculate progress, or infer dates/status from elapsed time.
- Optional season and car links use stable IDs and must reference records in the same team. Preserve those links if a referenced record is archived later.

## Work list

- [ ] Add a migration for the project table, team/reference foreign keys, shared metadata fields, and indexes for active-team listing, status/category, season, and car.
- [ ] Register the stable project record kind in ARCH-05 before project audit events or History routing are added.
- [ ] Add repository create, get-by-ID, update-field, archive, and list operations following repository ownership/error conventions.
- [ ] Scope every operation by team and support deterministic ordering plus archived inclusion for history/detail access.
- [ ] Define optional date storage using the Phase 4 entered-date convention; allow unknown dates and do not auto-fill actual dates.
- [ ] Add migration and SQLite integration tests for CRUD, optional links, same-team constraints, archived records, ordering, and isolation.

## Acceptance checks

- [ ] Migration creates no project rows, default categories, statuses, or development data.
- [ ] Project data composes `apl_record_meta`; it does not duplicate archive/timestamp policy.
- [ ] Stable IDs and foreign keys preserve project links if related display names change.
- [ ] A project cannot link to another team's season/car or be read through a different team scope.
- [ ] Repository errors and allocation behavior follow existing repository patterns; tests cover empty and populated results.

## Dependencies / boundaries

- Depends on ARCH-04 shared record metadata, ARCH-05 record kinds, Phase 3 season/car repositories, and the Phase 1 migration/repository foundations.
- This item adds persistence only; application validation/audit is in 5.2, updates are in 5.3–5.4, and transaction links are in 5.5.
- No project budget field, generated status vocabulary, progress percentage, or automatic completion date is added here.
