# 5.6 — Add project list and filters

**Status:** Done  
**Goal:** Make active-team projects easy to scan and find without implying progress or completeness.

## Work list

- [x] Add a project list in the Development view scoped to the active team by default.
- [x] Show useful entered fields: title, user-entered status, category, known date/season, and archived indicator where explicitly included.
- [x] Add filters for status, season, and category where present; expose active filter labels, result count, clear-filter action, and no-match state.
- [x] Exclude archived projects by default and provide an explicit way to include them for historical review.
- [x] Preserve selected row and filters when opening details or returning from a form/dialog.
- [x] Add headless screen/controller tests and TUI smoke coverage for empty, populated, filtered, archived, and switched-team views.

## Acceptance checks

- [x] Default list cannot leak another team's projects.
- [x] Missing status/category/date is visibly missing, not replaced with an inferred default.
- [x] Filtering does not mutate records and archived inclusion is explicit.
- [x] Keyboard and mouse can select/open records, clear filters, and access create actions.
- [x] The list uses shared TUI behavior and avoids putting project feature logic back into the shell event loop.
