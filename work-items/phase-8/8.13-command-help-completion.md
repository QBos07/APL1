# 8.13 — Complete command help, usage, and completion

**Status:** Planned  
**Goal:** Make the complete command surface discoverable and ensure help never advertises unsupported behavior.

## Work list

- [ ] Generate command help, aliases, required/optional arguments, valid options, and completion candidates from the command registry or a single authoritative definition.
- [ ] Document each route's direct-execution versus dialog-handoff behavior, team scope, confirmation requirements, and ambiguity handling.
- [ ] Add contextual help for every command family and subcommand in 8.7–8.12.
- [ ] Provide useful usage errors and suggestions for unknown subcommands/options, missing values, invalid value formats, and ambiguous targets.
- [ ] Ensure command completion respects the active team and current record context without leaking other-team records.
- [ ] Keep command history session-only and avoid treating it as the audit log or persisting sensitive typed text.

## Acceptance checks

- [ ] Every action in the 8.6 parity matrix appears in help/completion or has an explicit discoverable parent command that lists it.
- [ ] Help is derived from the same registry used for dispatch; no stale examples claim unavailable routes.
- [ ] Invalid/incomplete syntax either produces an actionable usage message or opens the documented prefilled dialog.
- [ ] Completion never chooses an ambiguous record or executes a write.
- [ ] Help/completion tests cover every command family, required option, alias, and error category.

## Dependencies / boundaries

- Depends on [8.7](8.7-team-people-reference-commands.md) through [8.12](8.12-overview-history-utility-commands.md), ARCH-08 dispatch, and the Phase 2 command registry.
- Does not add a separate command grammar or arbitrary command execution.
