# 8.14 — Verify full window-command parity

**Status:** Planned  
**Goal:** Prove that a user can complete every supported window workflow through commands with equivalent results and safeguards.

## Work list

- [ ] Turn every row in the 8.6 matrix into a test case or an explicitly justified shared parameterized test.
- [ ] For each write action, run the same scenario from the window and from a complete command, then compare persisted rows, derived views, audit events, and navigation/selection outcome.
- [ ] For each create/edit workflow, test an incomplete command opens the right prefilled dialog and a cancelled dialog performs no write.
- [ ] Cover active-team isolation, explicit all-team reads, duplicate/ambiguous identifiers, archive/destructive confirmation, validation errors, and database rollback.
- [ ] Include ledger opening balance → income/expense → correction → budget report and linked project/part transaction scenarios.
- [ ] Extend the end-to-end TUI smoke test to exercise a representative command in every window and verify persistence after restart.
- [ ] Add a guard/test that flags any newly registered window action without a command/help/completion/parity-matrix entry.

## Acceptance checks

- [ ] No unchecked or uncovered user-visible action remains in the parity matrix.
- [ ] Menu/window and command paths use the same use cases and produce equivalent persistence, audit, calculation, and confirmation behavior.
- [ ] Incomplete, invalid, ambiguous, and cancelled commands do not perform unintended writes.
- [ ] Ledger corrections, linked costs, team isolation, batch outcomes, and missing-data behavior are covered end-to-end.
- [ ] Full build, unit/integration/TUI tests, static/format checks, and smoke test pass.

## Dependencies / boundaries

- Depends on [8.6](8.6-window-command-parity-inventory.md) through [8.13](8.13-command-help-completion.md), plus Phase 2–7 windows and ARCH-08.
- This is verification and gap closure only; any uncovered action becomes a focused earlier command-route task rather than a waiver.
