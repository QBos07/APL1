# 8.6 — Inventory window actions and define command parity

**Status:** Planned  
**Goal:** Establish a finite, reviewable list of all actions the command interface must cover before adding the remaining routes.

## Work list

- [ ] Inventory every user-visible action in Overview, Teams, People, Events & Outcomes, Money, Development, Parts, History, Settings, Help, and About, including top-bar menus, tabs, row/detail actions, dialogs, filters, and reports.
- [ ] For each action, record its command shape, whether it executes directly or opens a prefilled dialog, required confirmation/choice behavior, active-team scope, use case, and parity-test case.
- [ ] Include existing `:view`, `:team`, driver/membership, season, and car commands in the inventory; identify partial routes rather than assuming an existing command family is complete.
- [ ] Mark actions that are terminal mechanics only (focus movement, pointer movement, resize) so the matrix does not invent meaningless commands for them.
- [ ] Map each missing/partial action to 8.7–8.12 and add any omitted route as a small work item before declaring the matrix complete.
- [ ] Keep the matrix versioned alongside the command registry or in a checked-in test fixture so future window actions cannot silently ship without command coverage.

## Acceptance checks

- [ ] Every user-visible action that changes navigation, filters, selection, view state, or domain data has an explicit command route or command-to-dialog handoff.
- [ ] The ledger matrix includes opening balance, income, expense, transaction detail/list, corrections, budget plans, and reports.
- [ ] No action is marked covered solely because another command uses the same noun; each distinct window action has its own route/usage and test mapping.
- [ ] The matrix identifies team context, ambiguity, destructive confirmation, and incomplete-input handoff behavior.
- [ ] The full matrix is the acceptance source for 8.14 and future parity work.

## Dependencies / boundaries

- Depends on the current Phase 2 command registry, Phase 3 reference commands, and completed Phase 4–7 windows.
- Inventory first; route implementation follows in 8.7–8.12.
- Does not add arbitrary SQL/shell commands or command aliases for low-level terminal mechanics.
