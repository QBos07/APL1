# 8.11 — Add complete event and outcome commands

**Status:** Planned  
**Goal:** Make event, session, and manually entered outcome workflows available through commands without changing missing-data semantics.

## Work list

- [ ] Add event/session list, show, create, edit, and archive routes for actions offered by Events & Outcomes.
- [ ] Add outcome list/detail and single-entry commands, plus batch-entry commands matching the window's review-and-save-all behavior.
- [ ] Add outcome correction routes that show prior and proposed values and use the same correction history operation.
- [ ] Add commands for recorded-value summaries/reports exposed by Events & Outcomes, preserving each report's scope and missing-value semantics.
- [ ] Support event/season/session/driver and date filters exposed by the window; keep the active scope visible.
- [ ] For incomplete or ambiguous commands, open the matching form/choice dialog with supplied values prefilled.
- [ ] Preserve missing fields as missing, identify drivers with no record, and never infer a DNF/zero/default result.

## Acceptance checks

- [ ] Every event/session/outcome action in the parity matrix is command-accessible or hands off to the same dialog.
- [ ] Batch commands validate all rows before save and have the same all-or-none behavior as the window.
- [ ] Duplicate driver/session targets are handled with the same explicit choice/edit behavior as the UI.
- [ ] Corrections preserve old values and audit history; command and window views show the same result.
- [ ] No command creates schedules, sessions, drivers, or outcomes automatically.

## Dependencies / boundaries

- Depends on [8.6](8.6-window-command-parity-inventory.md), Phase 7 operations/screens, 8.5 event filters, and ARCH-08.
- Does not add simulation, implicit scoring, or generated event data.
