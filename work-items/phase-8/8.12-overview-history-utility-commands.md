# 8.12 — Add overview, history, and utility-window commands

**Status:** Planned  
**Goal:** Cover the remaining non-entry windows and cross-record actions from the command line.

## Work list

- [ ] Cover every Overview menu/body action, including active-team and explicit all-team scopes, with matching navigation/report commands.
- [ ] Add History commands for list, team/record/action/date filters, clear filters, event detail, and opening the affected record when a route exists.
- [ ] Add commands for Settings actions that are actually available in the current window; read-only settings/database information must return the same values and scope.
- [ ] Ensure Help, About, and version/build-information actions are reachable from commands, including contextual command help.
- [ ] Add or align commands for all window-level navigation actions and aliases in the 8.6 matrix.
- [ ] Preserve active-team/all-team scope and filtered-list position when commands open details or change views.

## Acceptance checks

- [ ] No Overview, History, Settings, Help, About, or navigation action from the parity matrix is missing a command equivalent.
- [ ] History commands are read-only and cannot edit/delete audit records.
- [ ] Global/all-team behavior is explicit; commands do not silently widen active-team scope.
- [ ] Opening an affected record resolves through the stable record-kind routing registry or reports that no route exists.
- [ ] Utility commands do not expose arbitrary SQL, shell, or hidden settings mutation.

## Dependencies / boundaries

- Depends on [8.6](8.6-window-command-parity-inventory.md), Phase 2 navigation/help commands, 8.1–8.2 history work, ARCH-05 routing, and ARCH-08.
- This item covers window actions, not terminal-level pointer, focus, or resize mechanics.
