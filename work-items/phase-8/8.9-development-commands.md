# 8.9 — Add complete development commands

**Status:** Planned  
**Goal:** Make all Development-window project and update actions available through commands.

## Work list

- [ ] Add project list/show/create/edit/archive commands for every corresponding window action.
- [ ] Add dated update/log commands with required date/summary and optional status/notes; use the same update operation and dialog handoff.
- [ ] Add commands for any project-window action to link/open an existing ledger transaction, without creating a duplicate cost record.
- [ ] Add command access to project timeline and linked-cost details/summary wherever those actions are available in the Development window.
- [ ] Support status, season, and category filters/search exposed by Development; retain filter context when opening project detail.
- [ ] Require explicit project resolution for ambiguous names and preserve active-team scoping.
- [ ] Route complete writes directly through Phase 5 use cases; route incomplete writes to the corresponding prefilled form.

## Acceptance checks

- [ ] Every project/update list, detail, filter, create, edit, archive, and log action in the parity matrix is command-accessible.
- [ ] Commands do not calculate progress, infer completion dates, or create independent actual costs.
- [ ] Archived-project behavior, audit history, team/reference validation, and cancellation match the window workflow.
- [ ] Linked-cost displays remain ledger-derived and match the same corrected net totals as Money.

## Dependencies / boundaries

- Depends on [8.6](8.6-window-command-parity-inventory.md), Phase 5 use cases/forms/screens, 8.5 development filters, and ARCH-08.
- Uses the forms/handoff boundary established in 5.8; no separate command-only business rules.
